# 鸽鸽词典 V1.11.1

本版本只修一件事：**截图 OCR 取词是黑屏的**。没有新功能，也没有数据库升级。

## 修复

### 截图取词不再是黑屏

- **原因**：框选窗被建成「透明窗」，但里面的页面是不透明的：先铺了应用主题的底色，上面又盖了一层 40% 的黑遮罩。暗色主题下整屏是近黑的 `rgb(19,19,17)`，亮色主题下是一块灰板，桌面从来没有透出来过。这个问题从 v1.6.0 起就有。
- **现在**：按下热键的瞬间，先把光标所在的那块屏幕截下来（只放在内存里，不写磁盘、不上传），再显示一个不透明的全屏置顶窗，把这张**静止的画面**压暗，供你拖拽框选。窗口在画面画好之前一直是隐藏的，所以不依赖系统的窗口透明，也和应用的浅色 / 深色主题无关。截下来整屏纯黑会被当作错误报出来，而不是显示出来。
- 旧流程里的另外几个毛病也一并没有了：框选后先隐藏窗口、等 120 毫秒再重新截屏（有竞态）；截图经过一次 PNG 来回转换，红蓝通道被对调。现在识别用的就是你看到的那张画面的原始像素，框选区域按画面像素精确对应（在 150% 缩放的主屏上实测，拖出的框与读取的区域逐像素一致）。
- 框里没有识别出文字，或者框到的是一块纯色，会写明原因，并且可以在同一张画面上重新框选，不用再按一次热键。

### 缺少英文 OCR 识别包时，说清楚怎么办

- 应用只用**英文**识别引擎读英文。以前没有英文识别包时，会悄悄改用别的语言的引擎，把 Hello 读成 He110、Library 读成 Librany'、dog 读成 00g，查词当然查不到。
- 现在没有英文识别包时，框选窗上会给出一张提示卡：写明本机装了哪些识别包、该去哪里添加，并有「打开系统语言设置」按钮；设置页的「检测 OCR 可用性」给出同样的提示和按钮。
- 添加方法：设置 → 时间和语言 → 语言和区域 → 添加 English (United States) → 它的「语言选项」→ 勾选「光学字符识别」。

### 出了问题看得见

- 热键和托盘菜单没能开始截图取词时，会弹出系统对话框说明原因，不再什么都不发生；设置页的「立即框选取词」把原因显示在页面里。
- 框选窗的页面 10 秒内没有把画面显示出来，窗口会自动关闭并提示，热键不会就此失灵。
- 键盘上按住热键不放（自动重复）只会打开一个框选窗，不会重复截屏。
- 设置页里写着「可在下方立即框选做单次测试」，现在「启用截图取词」关着时，这个按钮确实能用。
- 从托盘菜单进入时，会先等 0.3 秒让菜单收起，再截屏，画面里不该再留着托盘菜单。

## 工程

- `src-tauri/src/ocr.rs` 重写：截屏（GDI `BitBlt`，`SRCCOPY | CAPTUREBLT`）、内存里的画面仓库、裁剪、BGRA 像素直接交给 `OcrEngine`、严格的识别语言选择（必须是所要的语言或它的变体，不会用别的语言顶替）。去掉了 `image` 依赖。
- 框选页（`src/pages/OcrSelect.tsx`）重写，画面解码与坐标映射在 `src/lib/ocr-frame.ts`，带测试；`/ocr-select` 路由不再套应用的主题和外层容器。
- 前端测试增加到 47 个文件 742 项；Rust 单元测试 323 项（其中 OCR 相关 25 项：像素布局、裁剪、纯色判断、语言选择与提示文案、重复触发的防护）。
- 版本三处同步 1.11.1（`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`，两个锁文件随之更新）。

## 升级说明

- **没有数据迁移**：schema 仍是 v7，设置不变，应用内更新即可；退回 v1.11.0 不需要处理数据目录。
- **请先装好英文 OCR 识别包**（见上面的添加方法）；没装时框选窗会给出提示卡，而不是黑屏。识别语言仍由设置里的 `ocr.language` 决定，默认 `en-US`，界面里没有这个入口。
- 框选时看到的是按下热键那一刻的**静止画面**：视频会停在那一帧，弹出的悬浮提示也停在那一刻。
- 框选窗只铺满光标所在的那一块屏幕。
- 截图只存在内存里，框选窗一关就丢弃，不写磁盘，不上传。

## 已知问题

- DRM 保护的视频、个别银行类客户端的窗口，系统不允许截屏，这些区域在画面里是黑的；框到的区域是纯色时，提示里会说明这一点。这是系统限制，不是应用的问题。
- 沿用 v1.11.0：界面样式里引用的网络字体被内容安全策略挡住，安装版显示系统后备字体。本版没有改动。

## 验证

开发机上的自动化检查通过：`npx tsc --noEmit`、`npm run lint`、`npm run build`、`npx vitest run`（47 个文件 742 项）、`cargo fmt --check`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo test --locked`（323 项）。

另外在一台双显示器的真机（主屏 2560×1600、缩放 150%，副屏 1920×1080、缩放 100%）上，用一个临时的壳程序运行了同一份开窗代码和真实的框选页：两块屏幕都能截到完整画面；框选窗精确覆盖光标所在的屏幕（置顶、有焦点、无边框）；真实的鼠标拖拽映射到画面像素时与所拖的框完全一致，识别出了文字；Esc 和鼠标右键都能关闭框选窗。这个壳程序没有进入仓库，也没有运行已安装的应用或碰用户数据。

自动化测试与这个壳程序够不到的部分，请按 `docs/QA-machine-checklist-v1.6.md` 的 B 组（B1–B13）在 Windows 实机验收。其中最需要实机确认的是：

- 按热键看到的是真实屏幕的冻结画面，暗色和亮色主题下都不是黑屏。
- 装好英文识别包后，框选一行英文能正确查词；没装时看到的是带「打开系统语言设置」的提示卡。
- 从托盘菜单进入截图取词时，画面里没有残留的托盘菜单。
- 在副屏、混合缩放（125% / 150%）下框选，识别出的就是框里的字。

# 鸽鸽词典 后续功能规划 — v1.9 / v1.10 交付与 v2.0 路线

文档状态：v1.9、v1.10 已交付（待发布），v2.0 为规划稿
适用版本：v1.8.0 之后
更新日期：2026-10-08
关联文档：`docs/ROADMAP-v1.1-v1.3.md`（早期路线与竞品分析）、`docs/PRD-v1.9-spec.md`（v1.9 开发规格）、`docs/compose/spec/v1.9.md`（v1.9 交付记录）、`docs/RELEASE-NOTES-v1.9.0.md`、`docs/PRD-v1.10-spec.md`（v1.10 开发规格）、`docs/compose/spec/v1.10.md`（v1.10 交付记录）、`docs/RELEASE-NOTES-v1.10.0.md`

### TL;DR

v1.8 之后，功能面已经足够宽：取词、领域解析、OCR、复习、阅读会话、Anki、术语表都在。这一轮从头读了一遍代码，结论是真正的风险不在「缺功能」，而在已有功能里的**信任债**：保存会悄悄覆盖用户数据、朗读的文本能让 PowerShell 执行命令、用量统计的数字是编的、「重新解析」按钮根本没调用模型、托盘开关的勾选与真实状态对不上。这些问题每一个都比一个新功能更伤用户对产品的信任。

所以 v1.9 的取舍是：**先还债，再只加两个功能**。两个功能分别补上最基础的反馈回路——「我查过什么还能找回来」（查词历史）和「我的学习到底有没有在发生」（学习洞察）。v1.10（已交付）解决「模型调用不稳」与「大词库不顺」两个已被测量出来的痛点，并补上批量补全、复习「有点难」与每周回顾；v2.0 的主题是发布信任（代码签名等），而不是再加取词入口。

## 一、现状评估

### 1.1 项目是什么、做得好的地方

Windows 桌面英语词典（Tauri 2 + React + Rust），Ctrl+C 即查，由用户自带的大模型做词典级解析，数据全在本机 SQLite。与同类产品相比，「桌面全局取词 + 领域深度解析 + 本地生词沉淀」这一层依旧没有强竞品（见 `ROADMAP-v1.1-v1.3.md` 竞品矩阵）。

做得好的部分：零服务端与 DPAPI 密钥、迁移前备份与失败回滚、统一的 `prepare_lookup` 查词管道（v1.7）、带单测的内容过滤与剪贴板去重、模块已拆出 `lookup.rs`（v1.8）。

### 1.2 这一轮发现的问题

| 编号 | 问题 | 后果 | 类别 | v1.9 |
| --- | --- | --- | --- | --- |
| P1 | 朗读文本被拼进 PowerShell 源码，只转义了 ASCII 引号；弯引号（U+2018/2019 等）同样是单引号分隔符 | 复制一段含弯引号的文字会让朗读静默失败；构造过的文本可以执行任意命令（本机已复现） | 安全 | 已修：文本、语音、语速改走环境变量，脚本是编译期常量 |
| P2 | 查词窗口保存时构造整词并整体替换 | 再次查已收藏的词会把掌握度、备注、标签重置，丢掉 Anki 关联，还可能产生重复词条 | 数据 | 已修：保存改为与库中已有词合并 |
| P3 | Anki 回写的 note id 按位置与词配对，而查询按时间倒序并丢弃未知 id | note id 落到别的词上；`anki_note_id` 列从未被写入 | 数据 | 已修：按词自身 id 配对，单事务写回 |
| P4 | `main` 上 `cargo fmt --check` 失败 | CI 红灯，其后的 `cargo test` 被跳过 | 工程 | 已修 |

| P6 | 「撤销收藏」只把按钮翻回去 | 词仍留在生词库里 | 数据 | 已修：撤销真正删除或还原 |
| P7 | 查词窗与 OCR 窗每次冷启动加载整个生词库 | 词库越大弹窗越慢 | 性能 | 已修：这两个窗口只查需要的那一个词 |

| P9 | 词条详情的「重新解析」只等 1.3 秒、改 `savedAt` | 声称「已用某模型重新解析」，实际没调用任何模型，还把词挪到了库顶和另一个阅读会话 | 信任 | 已修：真正强制刷新、合并保存、可回滚 |
| P10 | 用量统计在「保存」时才计一次，且 token 恒为 0 | 「今日查询」其实是「今日保存」，token 永远 0.0k | 信任 | 已修：在出结果处统一计数并估算 token |
| P11 | 21 个无人引用的文件（原型期的演示与 mock），约 2700 行，其中还带着旧的覆盖式保存 | 噪声与误改风险；安装包多带约 340 KB 壁纸 | 维护 | 已删 |
| P12 | 批量导入对每一行线性扫描全库 | 3000 行导入 3000 词用 9.6 秒 | 性能 | 已修：哈希索引，约 1 秒 |
| P13 | 托盘「划词即查」的勾选与实际状态不同步；「暂停 30 分钟」不可取消，且到点会把用户之后手动关掉的监听又打开 | 状态说谎 | 体验 | 已修：统一的开关对象，勾选随状态变化，暂停可取消 |
| P14 | 朗读用系统默认（通常是中文）语音读英文；设置页的试听用浏览器语音，与真正朗读的 Windows 语音不一致 | 听到的与试听的不是同一个声音 | 体验 | 已修：优先英文语音；设置页列出本机已安装语音并用原生引擎试听 |

| P17 | 生词库搜索每个按键都对全库重新过滤，每一行都重复渲染；「全选」以「已选数等于列表数」判断 | 大词库卡顿；已选但被筛掉的词会让「全选」框误判为全选 | 性能 / 正确性 | 已修 |
| P18 | `parse_entry` 在解析失败时把模型输出的前 500 字写进日志 | 违背 v1.5 对用户的承诺「日志不打印译文正文」 | 隐私 | 已修：日志只记长度与出错位置 |
| P19 | clippy 报二十余条警告，含 10 个参数的函数与 10 元素元组 | 难读、难改 | 维护 | 已清零：调用参数与查词计划改为结构体 |

## 二、v1.9 — 先还信任债，再补两个反馈回路（已交付）

定位：不加新的取词入口。修复上表问题，并补上「查过的词找得回」与「学习看得见」。

### 2.1 新功能

| 编号 | 内容 | 要点 |
| --- | --- | --- |
| E1 | 查词历史 | schema v6 新增 `lookup_history`；同一个词（拼写与空格归一化）只占一行并累计次数，保留最近 500 条；生词库新增「历史」页，按天分组、可搜索、标出已收藏、一键再次打开（缓存仍有效则零成本）；设置里可关闭记录、查看条数、一键清空 |
| E2 | 学习洞察 | 新页面 `/insights`：连续学习天数（今天还没学不算断）、7 / 30 / 90 天活动曲线、掌握程度分布、复习档位与正确率、常查的词、易错的词、生词来源 Top。数据全部来自本机既有的表，回到窗口时自动刷新 |
| E3 | 托盘与朗读 | 托盘「划词即查」勾选与真实状态一致；暂停 30 分钟可随时取消；设置页列出本机已安装语音，试听走原生引擎 |

「学习洞察」不是 `ROADMAP-v1.1-v1.3.md` 里「明确不做」的本地用量统计面板：那一项针对的是账单与 token 用量，价值确实低；洞察页回答的是「我学了多少、学得怎么样」。

### 2.2 工程

- schema 升到 v6，且**旧版本备份仍可恢复**：恢复时按备份自己那个版本的要求校验，复制进来后立即升级；比当前应用更新的备份会被明确拒绝，而不是被半懂不懂地打开。
- `cargo clippy --all-targets` 零警告；`llm.rs` 的 10 参数函数改为 `ModelCall` 结构体，`lookup.rs` 的 10 元素元组改为 `LookupPlan`。
- 前端：生词库的过滤与排序抽成纯函数（`library-list.ts`，有测试），列表行 memo 化，搜索词用 `useDeferredValue` 延后。
- 测试：vitest 每个用例 30 秒超时（繁忙机器上约 1 秒的用例曾跑到 8 秒而失败）；测试环境补上 `__APP_VERSION__`。

详细设计与验证记录见 `docs/PRD-v1.9-spec.md` 与 `docs/compose/spec/v1.9.md`。

## 三、v1.10 — 模型调用更稳，大词库更顺（已交付）

定位：处理 v1.9 期间被量出来、但不属于「信任债」的两个痛点，把质量门禁补齐，并补上三个让日常使用更完整的功能。

规划与实际的差别写在「交付情况」一列；顺序与规划一致（F3 → F1 → F2 → F4 → F5 → F6 → F7）。详细设计与验证记录见 `docs/PRD-v1.10-spec.md` 与 `docs/compose/spec/v1.10.md`。

| 编号 | 内容 | 优先级 | 交付情况 |
| --- | --- | --- | --- |
| F1 | 备用模型：主模型出问题时自动改用用户配置的备用提供商重试一次，并在结果里标明用了哪个 | P1 | 已交付。触发的错误码比规划多一个：`rate_limit` / `server` / `timeout` / `network`；`auth` / `model` / 解析失败不触发，免得盖住配置错误；备用 Key 同样走 DPAPI；答案存在主模型的缓存键下；本地统计新增「备用模型接管」。启用后备用服务会收到与主模型相同的选中文本，设置页与 README 都写明 |
| F2 | 生词库行虚拟化 | P1 | 已交付。规划是「五千词以上才处理」，实际从 400 词起窗口化：表格只画可见行与余量，占位行撑住高度，读屏器通过 `aria-rowcount` 听到真实长度；卡片视图用 `content-visibility` |
| F3 | CI 补 clippy 门禁并固定工具链 | P1 | 已交付。`rust-toolchain.toml` 固定 1.95.0；CI 与发布流程按它安装；`cargo clippy --locked --all-targets -- -D warnings`。耗时预算类测试的相对判断已在 v1.9 完成，没有重复 |
| F4 | 复习增加「有点难」，洞察页加复习日历 | P2 | 已交付。答案是「认识 / 有点难 / 不认识」（键 1 / 2 / 3，**键 2 的含义变了**），「有点难」留在原档、明天再见；schema v7（`hard_count`）；洞察页是 12 周复习日历，「易错的词」按「答错 × 2 + 有点难」排序 |
| F5 | 批量补全 | P2 | 已交付。只填空缺、每词一个事务、可暂停 / 继续 / 停止；续跑不需要保存状态（还光秃的词就是剩下的）；每天额度默认 10 万 token（无效值回到默认，`0` 才是不限制）、三档节奏、按错误种类区分的重试表；每个词都会遇到的失败整轮停下；批量请求不进历史与查询次数，token 计入用量 |
| F6 | 重新解析遇到词形变化时让用户选 | P3 | 已交付。比规划多一个选项：「更新「x」/ 另存为「y」/ 都不要」；另存可撤销，库里已有则更新、不重复；后端拒绝按 id 保存另一个 lemma 的答案 |
| F7 | 洞察页周报与每周目标 | P3 | 已交付。「每周回顾」：本周逐日、每周目标（1–7 天）、可保存 / 复制的 Markdown 周报（本周或上周）；数据没覆盖整周就明说，不当作没学；「本周新增」改名为「近 7 天新增」 |

没有放进 v1.10 的：多个备用模型的链式回退（一个就够，且只试一次）、常驻后台的自动补全（只有用户点了才运行）。

## 五、明确不做（沿用并补充）

`ROADMAP-v1.1-v1.3.md` 中的八项依然成立：多语种、浏览器扩展、云同步与账号、完整 SRS、整页翻译、写作润色、真人发音音频、账单式用量面板。补充：

| 功能 | 不做的理由 |
| --- | --- |
| 把查词历史上传或同步 | 历史里有用户选中的文本与来源应用，属于最敏感的一类数据。它只存在本机，并且可以关闭、可以一键清空 |
| 常驻鼠标钩子划词 | 误触发与安全软件误报的代价高于收益，Ctrl+C 与截图 OCR 已覆盖主要场景 |
| 内置免费模型额度 | 会引入服务端与成本，违背「零服务端、自带 Key」 |

## 七、技术考量

- v1.10 F1 在设置里增加了备用提供商，并由 `ask_services` 先主后备地调用；v1.9 的 `ModelCall` 结构体正是为此铺的路。备用调用只在「换个服务可能有用」的错误码上触发，鉴权失败（`auth`）与模型不存在（`model`）不会换个提供商再试，那只会掩盖配置错误。
- v1.10 F4 的「有点难」给 `review_state` 增加了 `hard_count`（schema v7）；沿用单事务、预迁移备份、失败回滚与单测的既有做法，并扩充 v1.9 补齐的「旧备份可恢复」测试。
- v1.10 F5 受 token 预算约束，复用 v1.9 的 token 估算，并把批量补全的开始、每个词的结果与结束写进本机 `local_events`（只带错误码与结束原因，不带词本身），不上传。

## [S1] Problem

v1.9 还完信任债之后，日常使用里剩下的摩擦是：

1. **模型偶尔不稳**：主模型遇到 429、5xx、超时或断网时，查词直接落到错误卡片，而用户常常另有一个可用的服务。
2. **大词库不顺**：数千词的库里，每次选中或滚动都要重绘并布局每一行；过滤与排序在 v1.9 已经便宜了，剩下的是渲染。
3. **复习的答案太粗**：只有「记得 / 不记得」，刚好想起来的词答对后直接跳到一周之后；洞察页也分不出「差点忘了」。
4. **导入的词是空壳**：从词表导入的词只有词形与释义，没有义项和例句，逐个手动查词是让这类词库用不起来的杂务。
5. **重新解析会悄悄改名**：模型返回另一个词形（running → run）时，保存会给词条改名，库里已有 run 时就变成两个 run。
6. **学习回顾缺一个时间尺度**：洞察页有 7 / 30 / 90 天的滚动数字，没有「这一周我学了几天」，也带不走。
7. **门禁没补齐**：clippy 已清零却不在 CI 里，工具链也没固定，新的 lint 会让无关的 PR 变红。
8. **顺手发现的小问题**：今日回顾按住数字键会连跳后面的卡、保存失败时丢掉这次作答、朗读按钮会翻面泄露释义；「本周新增」其实是滚动 7 天；设置页对复习规则的描述还是「答对 / 答错」两档。

## [S2] Design

### F3 门禁
- 工具链由 `rust-toolchain.toml` 决定，升级是一次有意的改动；CI 不再用 `stable`。

### F1 备用模型
- 只在「换个服务可能有用」的错误上触发；配置错误（`auth`、`model`）与解析失败不触发，免得盖住问题。
- 备用必须启用、字段齐全、能解密、且与主模型不是同一个服务才算数；只试一次。
- 答案存在主模型的缓存键下并标明回答者，两个都失败时错误码取主模型的、附上备用的原因。
- 启用后备用服务会收到与主模型相同的选中文本与上下文：开关说明、README 与发布说明都写明。

### F2 长列表
- 400 词以内不动（保证 Tab 与页内查找）；超过之后只画可见行 + 余量，占位行撑住高度；行固定一行；`aria-rowcount`；卡片交给 `content-visibility`。

### F4 复习
- 三个答案 → 一个纯函数调度；「有点难」留在原档、明天再见；`hard_count` 单事务迁移，旧备份恢复后升级。
- 答对率把「有点难」算作没答对；「易错的词」按「答错 × 2 + 有点难」。

### F5 批量补全
- 「光秃」= 单词 / 短语且没有义项没有例句；队列每次从数据库重算，所以续跑不需要状态；只填空；每词一个事务。
- 额度默认 10 万 token / 天，无效值回到默认而不是「不限制」；节奏三档；重试表区分「忙」与「坏」。
- 每个词都会遇到的失败整轮停下；连续 5 个词失败也停；批量请求安静，不进历史与查询次数，token 计入用量。

### F6 词形变化
- 先问再存；回答之前什么都不写；后端护栏阻止任何入口靠再保存给词条改名。

### F7 每周回顾
- 周由后端给的 `today` 推算；「学习了一天」与连续天数同一口径；数据没覆盖整周就明说，不写 0；周报独立读取 14 天数据，不依赖页面所选范围，也不读整个词库。

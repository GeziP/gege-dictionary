# 鸽鸽词典 v1.2 开发规格 — 学习闭环与版本送达

文档状态：开发规格，可直接进入实现
基线版本：v1.1.0（已发布，F0–F4 全部落地）
关联文档：`docs/PRD-v1.0.0-as-built.md`、`docs/ROADMAP-v1.1-v1.3.md`、`docs/PRD-v1.1-spec.md`
对应 Issue：#6（G0）、#7（G3）、#8（G1）、#9（G2）

### TL;DR

v1.2 解决产品当前最大的功能缺口：生词只进不出，收藏后再无回访路径。核心是以极轻量的方式补上学习闭环，同时建立版本送达能力，使后续迭代能真正触达存量用户。共四项：schema 版本化迁移机制、三档 Leitner 复习、阅读会话聚合、Tauri 自动更新。合计 9 个工作日，1 人完成。

## 源码核对结论

本规格基于 main 分支源码核对得出，以下四点直接决定了设计方案。

v1.1 已确认落地。`tauri.conf.json` 与 `Cargo.toml` 版本号均为 1.1.0；`db.rs` 中 `DB_FILENAME` 常量、`resolve_db_path` 兼容迁移、`integrity_check` 校验均已实现；`Cargo.toml` 已引入 `Win32_Security_Cryptography` 用于 DPAPI，并含 `sha2`、`futures-util`、`tokio-stream` 等流式与缓存所需依赖。

缺少 schema 迁移机制。当前 `initialize()` 完全依赖 `CREATE TABLE IF NOT EXISTS`，该模式只能新增表，无法变更既有表结构，也无法判断用户数据库处于哪个版本。v1.2 是项目首次需要真正的结构变更，必须先补齐此基础设施。

复习状态不能存入 `words.data`。`save_word` 采用 `INSERT OR REPLACE` 整体覆盖 JSON blob，若将复习进度写入其中，用户手动编辑一次释义即会清空进度。必须独立建表。

`mastery` 字段可直接复用。`words` 表已有 `mastery TEXT DEFAULT 'new'` 及 `idx_words_mastery` 索引，与三档 Leitner 天然对齐，无需新增字段，但语义需从手动标记改为复习流程自动驱动。

## Goals

### Business Goals

* 使激活用户的生词库七日内回访率达到 30% 以上，验证学习闭环成立。
* 建立版本送达通道，使新版本发布两周内存量用户升级率达到 60% 以上。
* 保持零服务端与零边际成本不变，自动更新复用 GitHub Releases 作为分发源。
* 将「收藏后能被重新遇见」建立为可感知的产品价值，支撑长期留存与迁移成本。

### User Goals

* 收藏的生词能在应用内被重新遇见，而非存完即忘。
* 每天的复习负担可预期且可控，不会因积压产生心理压力。
* 能回顾「读某篇文档时查了哪些词」，还原当时的学习场景。
* 无需手动下载安装包即可获得新版本。
* 升级过程中已有数据完整无损。

### Non-Goals

* 不做完整 SRS 算法（SM-2、FSRS 等），不做记忆曲线优化与间隔参数调优。
* 不做卡片变体（拼写填空、听写、选择题），仅做认识与不认识的二元判定。
* 不做复习提醒推送、连续打卡、成就徽章等游戏化激励。
* 不做跨设备同步复习进度，零服务端原则不变。
* 不做个人术语表与领域 Profile，留待 v1.3。

## User Stories

### 角色 A：持续积累的学习者

* 作为学习者，我想每天用几分钟回顾少量生词，以便真正记住而非只是收藏。
* 作为学习者，我想让复习量有明确上限，以便不因积压而放弃。
* 作为学习者，我想让答对的词逐渐减少出现频率，以便把时间花在真正的难点上。

### 角色 B：文献与文档阅读者

* 作为阅读者，我想查看某次阅读中集中查询的所有生词，以便复盘整篇材料的难点分布。
* 作为阅读者，我想对整个阅读会话批量打标签，以便按项目或主题归档。

### 角色 C：存量用户

* 作为存量用户，我想在应用内收到新版本提示并一键更新，以便无需手动下载安装包。
* 作为存量用户，我想确认更新不会影响已有生词库，以便放心升级。

## Functional Requirements

### G0 Schema 版本化迁移机制（Priority: P0，0.5 天）

后续所有结构变更的前置基础设施，必须最先完成。

* 版本标识
  * 使用 SQLite 内置的 `PRAGMA user_version` 记录 schema 版本，无需额外建表
  * v1.1 及更早的数据库 `user_version` 均为 0，视为基线版本
  * v1.2 目标版本为 2
* 迁移框架
  * 定义有序迁移列表，每项包含目标版本号与迁移 SQL
  * 启动时读取当前 `user_version`，依次应用所有更高版本的迁移，全程包裹在单个事务中
  * 任一迁移失败则整体回滚，保持数据库处于迁移前状态，并向前端返回明确错误
  * 迁移成功后更新 `user_version` 并记录日志
* 迁移前自动备份
  * 执行迁移前自动复制数据库为 `gege-premigrate-v{n}-YYYYMMDD-HHmmss.db`
  * 仅保留最近 3 份预迁移备份，超出则删除最旧的
  * 迁移失败时在错误提示中告知备份文件完整路径
* 既有 initialize 逻辑保留
  * `CREATE TABLE IF NOT EXISTS` 部分继续保留，用于全新安装的初始建表
  * 迁移逻辑在 `initialize()` 之后执行，两者职责分离

### G1 三档 Leitner 复习闭环（Priority: P0，3.5 天）

产品当前最大的功能缺口。核心原则是做轻量复习但不做完整 SRS：完整算法是重复造轮子且打不过 Anki，但完全不做复习，生词库就失去存在意义。

数据结构

```sql
CREATE TABLE IF NOT EXISTS review_state (
    word_id      TEXT PRIMARY KEY REFERENCES words(id) ON DELETE CASCADE,
    box          INTEGER NOT NULL DEFAULT 1,
    due_at       TEXT NOT NULL,
    last_result  TEXT,
    correct_count   INTEGER NOT NULL DEFAULT 0,
    wrong_count     INTEGER NOT NULL DEFAULT 0,
    reviewed_at  TEXT,
    created_at   TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_review_due ON review_state(due_at);
CREATE INDEX IF NOT EXISTS idx_review_box ON review_state(box);
```

独立建表而非并入 `words.data`，原因是 `save_word` 使用 `INSERT OR REPLACE` 整体覆盖，用户编辑释义会清空复习进度。

三档 Leitner 规则

| 档位 | 含义 | 答对间隔 | 对应 mastery |
| --- | --- | --- | --- |
| Box 1 | 新词 | 1 天后再现 | new |
| Box 2 | 巩固中 | 3 天后再现 | learning |
| Box 3 | 已掌握 | 7 天后再现 | mastered |

* 答对则升一档，已在 Box 3 则保持 Box 3 并按 7 天顺延
* 答错则直接回落至 Box 1，按 1 天顺延，不做渐进降级
* `due_at` 统一按本地日期计算，精确到日而非小时，避免用户因错过整点而困惑
* 每次答题同步更新 `words.mastery`，保持与既有筛选功能一致

队列生成

* 每日复习上限 20 词，可在设置页调整为 10 / 20 / 50 / 不限
* 优先级排序：逾期最久的优先，其次 Box 序号小的优先，最后按收藏时间升序
* 队列在进入复习页时一次性生成并固定，中途新增收藏不影响当前队列
* 无到期词时展示空状态，并提示下次复习时间

新词入池

* 收藏成功时自动创建 `review_state` 记录，`box` 为 1，`due_at` 为次日
* v1.2 迁移时为所有存量生词批量创建记录，`due_at` 按收藏时间分散到未来 1 至 7 天内，避免升级当天涌现数百词
* 段落与句子类型条目默认不入复习池，仅单词与短语入池，可在设置中开启

复习交互

* 入口：主窗口顶部常驻「今日回顾」卡片，显示待复习数量，无待复习时显示下次时间
* 卡片正面展示单词与音标，隐藏释义
* 用户可先自行回忆，点击或按空格键翻面展示完整解析
* 翻面后提供两个操作：认识（答对）、不认识（答错），支持键盘 1 与 2 快捷键
* 每次作答后立即写入数据库，中途退出不丢失进度
* 完成全部队列后展示简要总结：本次复习数、答对数、各档位变化

Tauri Command 签名

```
get_review_queue(limit: Option<u32>) -> Vec<ReviewCard>
submit_review(word_id: String, correct: bool) -> ReviewState
get_review_stats() -> ReviewStats   // 待复习数、各档位数量、下次到期时间
reset_review_state(word_id: String) -> ()
```

### G2 阅读会话（Priority: P1，2 天）

将零散的查词记录还原为学习场景，让用户能回顾「读这篇材料时查了哪些词」。

聚合规则

采用纯规则聚合，不引入 LLM 判断，避免额外 token 消耗与不确定性。

* 同一 `source_app` 且相邻两条记录的 `saved_at` 间隔小于 30 分钟，归为同一会话
* 间隔超过 30 分钟或来源应用变更，则切分为新会话
* 会话切分间隔可在设置页调整为 15 / 30 / 60 分钟
* 会话为查询时动态计算，不新增持久化表，避免维护一致性成本

数据结构

```sql
CREATE VIEW IF NOT EXISTS reading_sessions AS
-- 基于 words 表按 source_app 与 saved_at 间隔动态分组
-- 若视图性能不足，改为查询时在 Rust 侧分组
```

若 SQLite 视图实现窗口函数分组过于复杂，允许改为在 `db.rs` 中查询后于 Rust 侧完成分组，功能等价即可。

会话视图

* 生词库页面新增「会话」标签页，与既有列表视图并列
* 会话卡片展示：来源应用名、时间范围、词条数量、前若干个词的预览
* 点击会话展开该次阅读的全部生词
* 支持对整个会话批量打标签、批量导出、批量加入复习队列
* 会话按时间倒序排列，支持按来源应用筛选

Tauri Command 签名

```
get_reading_sessions(gap_minutes: u32, limit: u32, offset: u32) -> Vec<ReadingSession>
get_session_words(session_id: String) -> Vec<Word>
tag_session(session_id: String, tags: Vec<String>) -> u32
```

### G3 Tauri 自动更新（Priority: P0，2 天）

当前无更新通道，意味着 v1.2 及后续所有改进对存量用户的送达率接近零。现在装机量尚小，是植入成本最低的时刻。

依赖与配置

* `Cargo.toml` 新增 `tauri-plugin-updater = "2"`
* `package.json` 新增 `@tauri-apps/plugin-updater`
* `tauri.conf.json` 新增 `plugins.updater` 配置段，指定 `endpoints` 与 `pubkey`
* 更新源使用 GitHub Releases 的 `latest.json`，维持零服务端原则

签名密钥

必须由维护者本地执行，私钥不得进入仓库。

```bash
npx tauri signer generate -w ~/.tauri/gege-dictionary.key
```

* 公钥填入 `tauri.conf.json` 的 `pubkey` 字段
* 私钥与密码建议存入密码管理器
* 私钥一旦丢失，后续版本将无法通过已安装客户端的签名校验，只能要求全部用户手动重装
* CI 构建时通过环境变量 `TAURI_SIGNING_PRIVATE_KEY` 注入

更新流程

* 应用启动后延迟 30 秒静默检查更新，避免影响启动速度
* 设置页提供「立即检查更新」按钮与当前版本号显示
* 发现新版本时以非阻塞横幅提示，展示版本号与更新说明摘要
* 用户确认后下载，展示进度条，下载完成提示重启生效
* 提供「跳过此版本」与「稍后提醒」选项
* 设置页可关闭自动检查，改为完全手动

更新安全

* 仅接受签名校验通过的更新包，校验失败则中止并提示
* 检查更新仅发起版本号请求，不上报任何用户数据、设备信息或使用统计
* 更新前后数据库文件不受影响，升级后由 G0 迁移机制处理结构变更

## User Experience

### Entry Point & First-Time User Experience

* 存量用户升级到 v1.2 后首次启动，后台静默完成 schema 迁移与存量生词入池，全程无需操作
* 主窗口顶部首次出现「今日回顾」卡片，附一次性引导说明复习机制与每日上限
* 若存量生词较多，明确告知已将复习计划分散到未来一周，避免用户误以为需要一次性完成
* 设置页新增「复习」与「更新」两个分组

### Core Experience

* 步骤 1：用户打开主窗口，顶部展示今日待复习数量。
  * 无待复习时展示下次到期时间，不制造焦虑
  * 数量超过每日上限时显示上限值而非总积压数
* 步骤 2：进入复习页，展示第一张卡片。
  * 正面仅显示单词与音标，释义隐藏
  * 提示用户先自行回忆
  * 支持空格键翻面，降低操作成本
* 步骤 3：翻面查看完整解析。
  * 展示与查词窗口一致的结构化内容，包括语境义、例句、领域知识
  * 显示原始上下文与来源应用，帮助还原记忆
  * 提供发音按钮
* 步骤 4：作答并进入下一张。
  * 认识与不认识两个按钮，支持数字键 1 与 2
  * 作答后立即持久化，无需等待队列结束
  * 顶部进度条显示当前进度
* 步骤 5：完成队列，展示总结。
  * 本次复习数、答对数、升档与回落数量
  * 提供「继续复习」选项，可突破当日上限继续
* 步骤 6：切换至会话标签页回顾阅读场景。
  * 按时间倒序展示会话卡片
  * 展开可见该次阅读的全部生词
  * 支持批量打标签与导出

### Advanced Features & Edge Cases

* 复习过程中删除生词，需正确跳过并不中断队列
* 同一词在复习队列中被用户从生词库删除，`ON DELETE CASCADE` 自动清理复习状态
* 系统时区或日期变更时，`due_at` 按本地日期重新判定，不出现负数逾期
* 存量生词批量入池需在事务中完成，中断则整体回滚
* 更新下载中断或网络失败时，保留原版本可用，不留残缺文件
* 更新包签名校验失败时中止并明确提示，不静默忽略
* 会话聚合在生词数量达到万级时需保持响应，必要时限制单次查询范围

### UI/UX Highlights

* 复习卡片翻面使用轻量过渡动画，避免生硬跳变
* 认识与不认识两个按钮的视觉权重相当，不诱导用户选择某一侧
* 每日上限的存在需在界面上明示，让用户感知到负担可控
* 会话卡片以来源应用图标或名称作为视觉锚点，便于快速定位
* 更新提示使用非阻塞横幅而非模态弹窗，不打断当前操作
* 复习页支持完整键盘操作，无需触碰鼠标

## Narrative

一位研究生在过去三个月里用鸽鸽词典积累了两百多个生词。这些词老老实实躺在生词库里，他偶尔打开看看，但从没真正复习过——导出到 Anki 需要额外设置，他一直没抽出时间。那些查过的词，大部分还是记不住。

升级到 v1.2 后，他第一次打开主窗口，顶部多了一张卡片：今日待回顾 12 词。他点进去，第一张卡片只显示 `attenuation` 和音标。他想了两秒，隐约记得和信号衰减有关，按空格翻面——完整解析出现了，包括他当初查这个词时所在的那句话，以及来源标注的 PDF 文件名。他按下 1，卡片划走，进度条前进。

十二张卡片，四分钟。有三个词他没认出来，回落到第一档，明天会再见到。剩下九个升了档，最快也要三天后才会再出现。结束页面告诉他今天答对了九个。

第二天，卡片显示待回顾 8 词。第三天 11 词。数量始终在可控范围内，他也就一直没停下来。

两周后他切到会话标签页，看到「读那篇 IVD 综述时查的 23 个词」被聚合成一条记录。他给整个会话打上标签，导出成一份材料发给了同门。

对产品而言，这位用户的生词库第一次从存储变成了使用。他每天打开应用的理由，不再只是查词，还有回顾——这正是留存指标真正的支点。

## Success Metrics

### User-Centric Metrics

* 生词七日回访率：收藏后七日内在应用内被再次查看或复习的条目占比，目标 30% 以上。
* 复习功能启用率：激活用户中至少完成一次复习的比例，目标 50% 以上。
* 复习完成率：进入复习页后完成整个队列的比例，目标 70% 以上。
* 会话视图使用率：使用过会话标签页的用户占比，目标 20% 以上。
* 复习留存：首次复习后第七天仍在复习的用户占比，目标 40% 以上。

### Business Metrics

* 版本送达率：新版本发布两周内存量用户升级比例，目标 60% 以上。
* 更新失败率：下载或签名校验失败的比例，目标低于 2%。
* 数据迁移零事故：升级相关的数据丢失反馈为零。

### Technical Metrics

* Schema 迁移成功率 100%，失败时回滚成功率 100%。
* 复习队列生成耗时：万级生词库下低于 200ms。
* 会话聚合查询耗时：万级生词库下低于 500ms。
* 自动更新检查不影响启动速度，冷启动到托盘就绪时间不退化。

### Tracking Plan

沿用本地埋点原则，不做任何上传。

* schema_migration_started / schema_migration_completed / schema_migration_failed（含版本号与原因）
* review_queue_generated（含队列长度）
* review_card_answered（含 correct 与 box 变化）
* review_session_completed（含总数与正确数）
* review_limit_changed
* review_continued_beyond_limit
* reading_session_viewed / reading_session_expanded / reading_session_tagged
* updater_check_started / updater_update_available / updater_download_completed / updater_failed（含原因）
* updater_skipped_version / updater_auto_check_disabled

## Technical Considerations

### Technical Needs

* 改动集中于 `db.rs`（G0、G1、G2）、`lib.rs`（新增 Tauri commands）、前端新增复习页与会话标签页、`tauri.conf.json` 与 `Cargo.toml`（G3）。
* 迁移框架需独立模块并配备单元测试，覆盖从版本 0 升级、重复执行幂等、迁移失败回滚三类场景。
* 复习状态机需独立于 UI，便于单元测试档位流转与到期计算。
* 会话聚合若采用 Rust 侧分组，需注意大数据量下的内存占用。

### Integration Points

* GitHub Releases 作为更新源，需在发布流程中生成并上传 `latest.json`。
* 发布流程需引入签名步骤，CI 通过环境变量注入私钥。
* 复习卡片复用查词窗口的解析结果渲染组件，避免重复实现 Markdown 与结构化字段展示。

### Data Storage & Privacy

* 复习记录与会话数据均存于本地 SQLite，不上传。
* 自动更新仅发起版本号查询，不携带任何用户标识、设备信息或使用数据。
* 预迁移备份存于数据目录下，用户可自行查看与清理。

### Scalability & Performance

* `review_state` 表规模与生词数同量级，索引已覆盖 `due_at` 与 `box`，查询压力可忽略。
* 会话聚合是本版本最重的查询，需在万级数据下验证性能，必要时增加时间范围限制。
* 存量生词批量入池在极端情况下可能涉及数千条插入，需在单事务中批量执行。

### Potential Challenges

* 复习功能突破了 v1.0.0 PRD 中「不做 SRS」的 Non-Goal，需在文档中明确边界，防止范围蔓延为完整记忆系统。
* 签名私钥的保管是一次性但不可逆的风险点，丢失将导致更新通道永久失效。
* 存量用户升级当天的复习量分散策略若设计不当，会造成第一天涌现大量卡片而劝退用户。
* 会话聚合的 30 分钟阈值对不同使用习惯的适配度需实际验证，首版以可配置降低风险。

## Milestones & Sequencing

### Project Estimate

Small 偏上，9 个工作日。

### Team Size & Composition

1 人全栈，配合 AI 编码助手。

### Suggested Phases

阶段一：迁移基础设施（0.5 天）

* 关键交付：G0 schema 版本化迁移机制与预迁移备份
* 依赖：无
* 说明：所有后续结构变更的前提，必须最先完成且需充分测试回滚路径

阶段二：版本送达通道（2 天）

* 关键交付：G3 Tauri 自动更新，含密钥生成与发布流程调整
* 依赖：需维护者本地生成签名密钥对
* 说明：优先级高于复习功能。只有更新通道先建立，v1.2 的复习功能才能真正触达存量用户；若最后才做，本版本自身的送达率依然为零

阶段三：学习闭环（3.5 天）

* 关键交付：G1 三档 Leitner 复习，含数据表、状态机、复习页与存量入池迁移
* 依赖：G0 完成
* 说明：本版本工作量最大的一项，建议先完成后端状态机与单元测试，再实现前端交互

阶段四：场景还原（2 天）

* 关键交付：G2 阅读会话聚合与会话标签页
* 依赖：G0 完成
* 说明：独立性强，可在其他阶段出现阻塞时插入

阶段五：联调与发布（1 天）

* 关键交付：全链路验收、性能验证、README 与文档同步
* 依赖：前四阶段完成

### 发版检查清单

* 从 v1.1.0 实机升级验证：schema 迁移成功、生词数量一致、复习状态正确初始化
* 存量生词分散入池验证：升级当天待复习数不超过每日上限
* 复习状态机验证：升档、回落、到期计算、跨日期边界
* 会话聚合在万级数据下的响应时间验证
* 自动更新全流程验证：检查、下载、签名校验、安装、升级后数据完整
* 签名私钥已安全保管，公钥已正确填入配置
* 中断场景验证：复习中途退出、更新下载中断、迁移失败回滚
* README 补充复习功能说明与自动更新说明
* 路线图文档中 v1.2 状态更新为已完成

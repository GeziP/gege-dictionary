# v1.6 实机验收清单

适用版本：1.6.0 + 修复提交 `7a6108d`  
目的：自动化门禁与浏览器 mock 无法覆盖的原生路径，在装有 Windows 的真机上逐项验收。

## 环境前置

| 项 | 要求 |
|---|---|
| OS | Windows 10 1809+ / Windows 11 |
| OCR 语言包 | 设置 → 时间和语言 → 语言和区域 → 添加 English (United States) → 它的「语言选项」→ 勾选「光学字符识别」。没有它时应用会明确提示，**不会**改用别的语言引擎乱识别英文（实测中文引擎把 Hello 读成 He110、Library 读成 Librany） |
| Anki | 桌面版已启动，安装 AnkiConnect（默认 `127.0.0.1:8765`） |
| 显示器 | 至少一台副屏（或缩放 ≠100%）用于多屏 OCR |
| 安装包 | `Gege-Dictionary_1.6.0_x64-setup.exe` 或本地 `npx tauri build` 产物 |

## A. 复制即查（主路径）

| # | 步骤 | 期望 |
|---|------|------|
| A1 | 浏览器选中英文句子 → Ctrl+C | 弹出查词窗，无闪白 reload |

## B. 截图 OCR

框选方式（黑屏修复后）：按下热键的瞬间先把光标所在屏幕截下来，再用一个不透明的全屏置顶窗显示这张静态截图并压暗，在上面拖拽框选。窗口不依赖系统透明，所以与应用主题（亮/暗）无关；旧版「透明窗 + 不透明页面」在暗色主题下会整屏变黑。

| # | 步骤 | 期望 |
|---|------|------|
| B1 | 主屏 Ctrl+Shift+O，框选扫描 PDF 英文 | 先出现一张压暗的**冻结画面**（内容与按键瞬间的屏幕一致，不是黑屏）；框选后弹出查词窗；`sourceTitle` 为前台窗口标题 |
| B2 | 副屏上框选（光标在副屏） | 冻结画面铺满光标所在屏；识别内容与框选区域一致 |
| B3 | 混合 DPI（125%/150%）副屏框选 | 识别出的就是框里的字，无偏移 |
| B4 | 框选没有文字的区域 / 纯色区域 | 提示「没识别到文字…」或「这块是纯色的…」（后者还会说明可能是受保护内容），不写缓存；不用重新截屏即可再框一次 |
| B5 | 设置关闭「截图取词」 | 热键失效；托盘无「截图取词」项；设置页「立即框选取词」仍可做单次测试 |
| B6 | 修改热键为 `Control+Alt+O` 并失焦 | 新热键生效，旧热键失效 |
| B7 | 暗色、亮色主题各按一次热键 | 两种主题下看到的都是真实屏幕内容，没有整屏纯黑 / 纯灰 |
| B8 | 框选窗里按 Esc、点鼠标右键、点「取消」 | 立即关闭，无副作用，不弹查词窗 |
| B9 | 没装英文 OCR 识别包时按热键 | 冻结画面上出现可操作的提示卡（含「打开系统语言设置」）；设置页「检测 OCR 可用性」给出同样的提示 |
| B10 | 按住热键不放（键盘自动重复） | 只出现一个框选窗，不闪烁、不重复截屏 |
| B11 | 托盘菜单 → 截图取词 | 冻结画面里没有残留的托盘菜单（菜单收起后才截屏） |
| B12 | 对 DRM 受保护的视频 / 个别银行客户端框选 | 受保护区域在画面里是黑的（系统限制，不是 bug）；其余区域正常识别 |
| B13 | 截屏做不到时（如远程桌面已断开、屏幕已关闭） | 弹出原生错误对话框说明原因；不出现黑屏窗口；热键和托盘仍可再次使用 |

# 鸽鸽词典 v1.1 开发规格 — 体验与信任债偿还

文档状态：开发规格，可直接进入实现
基线版本：v1.0.0
关联文档：`docs/PRD-v1.0.0-as-built.md`、`docs/ROADMAP-v1.1-v1.3.md`
对应 Issue：#1（F0）、#2（F1）、#4（F2）、#3（F3）、#5（F4）

### TL;DR

v1.1 不新增产品能力，目标是偿还 v1.0.0 遗留的体验与信任债。共五项：修复会导致生词库「丢失」的数据目录迁移缺陷、接线已实现但未调用的本地缓存、实现真流式渲染、治理 Ctrl+C 误触发并改造查词窗口行为、将 API Key 改为 DPAPI 加密存储。合计 8 个工作日，1 人完成。

---

## Goals

### Business Goals

* 消除数据丢失级缺陷，避免早期用户因「生词全没了」而流失并形成负面口碑。
* 将剪贴板误触发率降至日常使用一小时内不超过 1 次，去除卸载的首要诱因。
* 消除明文存储 API Key 这一最易被公开质疑的安全短板。
* 通过缓存降低重复查询的 token 消耗，强化「自带 Key 成本可控」的产品主张。

### User Goals

* 迁移数据目录后生词库完好无损，备份文件可靠可恢复。
* 复制密码、代码、文件路径时不再被弹窗打断，也不担心内容外发。
* 长段落解析时立即看到译文开始出现，而非面对数秒空白。
* 重复查询同一个词时瞬间返回，不再等待也不再消耗 token。
* 查词窗口出现在视线附近且不抢走当前应用的输入焦点。

### Non-Goals

* 不新增复习、术语表、OCR 等功能，全部留待 v1.2 与 v1.3。
* 不做 Prompt 模板编辑器，v1.3 以预设风格形式替代。
* 不改变 Ctrl+C 作为主触发方式的基本设计，仅做过滤与模式扩展。

## User Stories

### 角色 A：已使用 v1.0.0 的存量用户

* 作为存量用户，我想在升级后自动找回因目录迁移而「消失」的生词，以便不必手动排查文件。
* 作为存量用户，我想让我的 API Key 自动转为加密存储，以便无需重新配置。

### 角色 B：在敏感环境工作的技术用户

* 作为技术用户，我想复制密码与密钥时不触发查词，以便避免内容被发送到第三方服务。
* 作为技术用户，我想复制代码片段与文件路径时保持安静，以便不被无关弹窗干扰。
* 作为技术用户，我想在特定应用前台时完全关闭监听，以便在密码管理器与终端中放心操作。

### 角色 C：长文本阅读者

* 作为阅读者，我想在复制段落后立即看到译文开始出现，以便判断是否值得继续等待。
* 作为阅读者，我想查词窗口出现在光标附近且不抢焦点，以便保持原应用的阅读与输入状态。
* 作为阅读者，我想重复查询同一个词时瞬间得到结果，以便快速回顾。

## Functional Requirements

### F0 数据目录迁移缺陷修复（Priority: P0，0.5 天）

问题：`db.rs` 中迁移与备份逻辑写入 `lexnote.db` 与 `lexnote-*.db`（LexNote 时期遗留命名），而应用实际打开 `gege.db`。用户执行「迁移数据目录」后重启，程序在新目录找不到 `gege.db` 便创建空库，表现为生词全部丢失。数据实际仍在旧目录，但用户无从得知，可能误删造成真实不可逆丢失。

* 统一常量：定义 `DB_FILENAME = "gege.db"` 与 `LEGACY_DB_FILENAME = "lexnote.db"`，移除所有硬编码字符串，迁移、备份、打开路径统一引用。
* 兼容式自动识别：启动打开数据库时，若存在 `gege.db` 则正常打开；若不存在但存在 `lexnote.db`，自动重命名为 `gege.db` 后打开并记录日志；两者皆无则创建新库。此步骤确保已踩坑用户升级后数据自动恢复。
* 迁移流程加固：迁移前校验目标目录可写与剩余空间；按「复制 → `PRAGMA integrity_check` 校验 → 更新配置 → 提示旧文件位置」顺序执行；失败时回滚配置保持原目录不变；成功后不自动删除旧文件，仅提示完整路径由用户自行清理。
* 备份命名：备份文件改为 `gege-backup-YYYYMMDD-HHmmss.db`。

### F1 本地缓存接线（Priority: P0，0.5 天）

背景：`db.rs` 中 `cache` 表、`get_cache`（含 30 天 TTL 判定）、`set_cache` 已全部实现，但查词主链路并未调用。本项不是从零开发，而是接线与缓存键设计。

* 缓存键设计：`sha256(normalized_selection + "|" + kind + "|" + model + "|" + template_version)`
    * `normalized_selection`：trim + 连续空白折叠为单空格；单词模式额外转小写，使 `Hello` 与 `hello` 命中同一条；段落与句子模式保留原始大小写，仅做空白归一
    * `kind`：word / phrase / sentence / paragraph，不同模式使用不同 Prompt，必须参与键计算
    * `model`：模型变更时结果应重新生成
    * `template_version`：Prompt 模板内容哈希前 8 位，模板调整后旧缓存自动失效
* 调用时机：计算键 → 查缓存命中且未过期则直接返回并标识「缓存」→ 未命中则请求 LLM → 成功后写入。LLM 失败或 JSON 解析失败时不写入缓存。
* 用户控制：查词窗口提供「重新解析」按钮跳过缓存并覆盖写入；设置页提供「清空缓存」并显示条目数与占用空间；缓存有效期可配置（7 / 30 / 90 天 / 永不过期，默认 30 天）。
* 清理策略：启动时异步清理超期记录；条目数超过 5000 条时按 `created_at` 淘汰至 4000 条。

### F2 真流式渲染（Priority: P0，3 天）

背景：`llm.rs` 中 `stream_lookup` 函数名与实现矛盾，请求体 `"stream": false` 为硬编码，实际是一次性返回。用户在解析完成前面对空白窗口，感知延迟通常 3 至 8 秒。这是 v1.1 唯一具备技术风险的任务。

* 双协议 SSE 支持
    * OpenAI：`/chat/completions`，`"stream": true`，增量字段为 `choices[0].delta.content`
    * Anthropic：`/v1/messages`，`"stream": true`，增量字段为 `content_block_delta.delta.text`，需正确处理 `message_start`、`content_block_delta`、`message_stop` 等事件类型
* 增量 JSON 字段提取：解析结果是结构化 JSON，而流式返回是逐字符片段，JSON 闭合前标准解析器无法处理中间态。需实现轻量扫描器维护字符缓冲区，跟踪括号深度、是否处于字符串内、是否处于转义序列；仅在深度为 1 时识别顶层 key；某字段值完整闭合时立即发射；已发射字段不重复发射。
* 渲染优先级
    * 第一批：translation、ipa_us、ipa_uk、pos（骨架先出）
    * 第二批：context_meaning、senses
    * 第三批：explanation、associations
    * 第四批：examples、collocations、register、领域知识扩展
    * 段落模式下 `translationPairs` 按数组元素逐条发射，实现逐句对照的渐进呈现
* 前后端事件契约：Rust 侧通过 Tauri Event 向 lookup 窗口推送
    * `lookup://delta`，载荷 `{ requestId, field, value }`
    * `lookup://done`，载荷 `{ requestId, raw, fromCache }`
    * `lookup://error`，载荷 `{ requestId, stage, message, retryable }`
    * `requestId` 用于丢弃过期请求的残留事件，应对用户快速连续复制
* 降级预案：流式请求失败或提供商不支持 `stream` 参数时自动回退非流式路径，用户无感；增量解析异常不中断流，待完整响应到达后走原有 JSON 修复层；设置页提供「禁用流式渲染」开关。
* 顺带修复：将名不副实的 `stream_lookup` 重命名，明确区分 `lookup_streaming` 与 `lookup_blocking`。

### F3 剪贴板误触发治理与窗口改造（Priority: P0，2.5 天）

问题一：`clipboard_watcher.rs` 中 `is_english_text` 过滤规则过于宽松，仅排除 URL、以 `{ [ <` 开头的文本、字母占比小于等于 0.4 的内容。英文密码、API Key、`C:\Users\...` 路径、不以括号开头的代码片段、英文人名、commit hash 均会触发弹窗并被发送至第三方 LLM。其中复制密码触发上传既是体验问题也是隐私事故。

问题二：窗口行为是打断式而非伴随式。`.center()` + `.always_on_top(true)` + `.focused(true)`，且每次查询 `close()` 旧窗口后 `sleep(200ms)` 重建。用户在 PDF 右下角复制，窗口却在屏幕正中弹出并抢走焦点。

* 三档触发模式
    * 智能模式（默认）：自动过滤敏感与非自然语言内容
    * 全量模式：保持 v1.0.0 行为，适合不愿漏查的用户
    * 双击 Ctrl+C：800ms 内连按两次才触发，适合对干扰零容忍的用户
    * 默认选智能模式的理由：安静但偶尔漏查，比吵闹但全覆盖更容易让用户长期保留应用
* 敏感内容识别（智能模式），命中任一则不触发
    * 疑似密钥：含 `sk-`、`ghp_`、`AKIA` 等前缀，或长度大于 20 且同时含大小写字母与数字且无空格
    * 疑似密码：长度 8 至 64、无空格、含特殊字符
    * 文件路径：匹配 `X:\...`、`/usr/...`、`./...`、`../...`
    * 代码特征：含 `=>`、`->`、`::`、`&&`、`||`、`function `、`const `、`def `、`import ` 等标记
    * 纯数字、纯符号、单个字符
    * Base64 与 Hex 特征串（长度大于 32 且字符集受限）
    * 邮箱地址、IP 地址
    * 识别逻辑集中于独立模块并配备单元测试
* 应用黑名单：内置常见密码管理器、终端类应用、远程桌面客户端；用户可增删，匹配前台窗口标题或进程名；黑名单应用前台时完全跳过轮询。
* 托盘快捷控制：新增「暂停监听」与「恢复监听」，暂停期间图标灰态；支持「暂停 30 分钟」定时选项，到期自动恢复。
* 窗口行为改造
    * 复用单一 lookup 窗口而非销毁重建，移除 200ms sleep
    * 定位改为光标附近，自动避让屏幕边缘，适配多显示器与高 DPI
    * 默认 `focused(false)`，不抢占原应用焦点与输入状态
    * 保留「钉住」与 Esc 关闭

### F4 API Key DPAPI 加密（Priority: P1，1 天）

背景：当前 API Key 以明文存于 settings 表。对以「零数据上传、本地优先、隐私可控」为卖点的开源工具，这是最易被公开质疑的点。

* 加密方案：使用 Windows DPAPI（`CryptProtectData` / `CryptUnprotectData`），以当前用户作用域加密。选择理由是无需用户设置主密码，密文与 Windows 用户账户绑定，数据库文件被复制到其他机器或其他用户也无法解密，与零额外心智负担的定位一致。
* 存储格式：settings 表中值改为 `dpapi:v1:<base64_ciphertext>`，前缀用于区分明文与密文，版本位为未来更换方案预留。
* 明文自动迁移：启动读取配置时，以 `dpapi:v1:` 开头则解密使用；为明文则自动加密回写并记录日志，用户无感；解密失败（如数据库被复制到其他机器）时不崩溃，清空该 Key 并引导重新配置并说明原因。
* 界面处理：Key 输入框默认掩码并提供「显示」切换；已保存 Key 回显为掩码（仅展示前 4 位与后 4 位）；不在任何日志、错误信息、崩溃报告中输出 Key 原文。
* 文档同步：README 隐私说明补充 DPAPI 加密说明。

## User Experience

### Entry Point & First-Time User Experience

* 存量用户升级后首次启动，后台静默完成两项迁移：数据库文件名兼容识别、API Key 明文转密文。全程无需用户操作，仅在日志中留痕。
* 若检测到用户曾使用过旧版迁移功能且当前库为空，在主窗口顶部展示一次性提示，说明旧数据位置与已自动恢复的结果。
* 新增设置项默认值即为推荐值，用户不进设置页也能获得改善后的体验。

### Core Experience

* 步骤 1：用户在任意应用中复制英文文本。
    * 智能模式下先经敏感内容识别与黑名单判断，命中则完全静默，无任何视觉反馈
    * 通过判断则进入查词流程
* 步骤 2：查词窗口在光标附近出现，不抢焦点。
    * 窗口复用而非重建，无关闭再打开的闪烁
    * 多显示器与高 DPI 环境下定位正确且不越界
    * 用户仍可继续在原应用中滚动与输入
* 步骤 3：结果渐进呈现。
    * 命中缓存时瞬时返回并标识「缓存」
    * 未命中时首先出现翻译与音标骨架，随后各字段陆续填充
    * 段落模式下逐句译文按顺序出现，无闪烁与错位
    * 流式失败时自动降级为一次性返回，用户侧无报错
* 步骤 4：收藏与后续操作，与 v1.0.0 一致。
    * 新增「重新解析」按钮，跳过缓存强制请求并覆盖缓存

### Advanced Features & Edge Cases

* 用户快速连续复制多段文本时，通过 `requestId` 丢弃过期事件，最终仅展示最后一次结果。
* 中途关闭窗口需正确终止流式请求，不留残留线程。
* 迁移到只读目录或空间不足时给出明确错误并回滚配置。
* 数据库被复制到其他机器时，应用不崩溃，提示需重新配置 Key。
* 提供商不支持流式参数时自动降级，且该状态应被记录以便后续排查。

### UI/UX Highlights

* 缓存命中需有明确但克制的视觉标识，不喧宾夺主。
* 托盘图标在暂停监听时呈灰态，状态一目了然。
* 三档触发模式在设置页以单选卡片呈现，每档附一句场景说明，避免用户凭名称猜测。
* 敏感内容被拦截时保持完全静默，不做任何提示，否则等于变相暴露用户复制了敏感信息。

## Narrative

一位后端工程师在排查线上问题，屏幕上同时开着终端、IDE 和一篇英文技术文档。在 v1.0.0 上，他每复制一段配置、一个文件路径、一次数据库密码，右下角都会弹出查词窗口并抢走焦点——他不得不按 Esc 关掉，再点回终端继续输入。更让他不安的是，那次复制的密码，很可能已经被发到了 LLM 服务商那里。

升级到 v1.1 后，这些干扰消失了。复制密码、路径、代码片段时应用完全静默；当他真正复制文档里的一段英文时，查词窗口在光标附近轻轻出现，没有抢走终端的输入焦点，译文几乎立刻开始逐句浮现，他扫一眼就继续读了下去。前一天查过的术语再次出现时，结果瞬间返回并标着「缓存」——既没有等待，也没有消耗额度。

对产品而言，这一版没有增加任何可以写进特性表的新能力，但它移除了三个最可能导致卸载的理由：数据丢失的恐慌、无休止的弹窗干扰、以及对隐私的疑虑。留存的地基由此才真正建立，v1.2 的学习闭环才有意义。

## Technical Considerations

### Technical Needs

* 改动集中于 `db.rs`（F0、F1）、`llm.rs`（F2）、`clipboard_watcher.rs` 与 `lib.rs`（F3）、设置相关模块（F4），无架构级变更。
* 敏感内容识别应独立为单独模块并配备完整单元测试，便于后续持续调优规则。
* 流式增量解析器同样需独立模块与单元测试，测试需覆盖字符串内含 `{`、`}`、`"`、转义引号、嵌套对象、字段值为 null、响应被截断等边界情况。

### Integration Points

* OpenAI 与 Anthropic 两套 SSE 格式差异需在协议适配层吸收，上层无感。
* Windows DPAPI 通过系统 API 调用，无第三方加密库依赖。
* 前台窗口标题获取沿用现有 `GetForegroundWindow` 与 `GetWindowTextW` 实现，黑名单匹配复用该能力。

### Data Storage & Privacy

* 被敏感识别拦截的内容不写入日志、不写入缓存、不发送任何请求。
* 缓存表存储的是解析结果而非原始敏感文本，但仍需确保拦截逻辑在缓存写入之前生效。
* API Key 密文与当前 Windows 用户绑定，跨机器复制数据库不可解密，此行为需在设置页明确告知。

### Scalability & Performance

* 缓存表增长受 5000 条上限约束，不构成存储压力。
* 流式渲染增加了前后端事件通信频次，需控制发射粒度，避免高频事件造成 UI 抖动。
* 剪贴板轮询保持现有 500ms 间隔，敏感识别为纯字符串运算，性能影响可忽略。

### Potential Challenges

* 增量 JSON 解析是全版本唯一高风险项，若三天内未达成可用状态，应果断启用降级预案不阻塞发版。
* 敏感内容识别规则过严会漏查正常词汇，过松则失去意义，需在真实使用中持续校准，首版以偏保守为宜。
* 窗口不抢焦点在部分全屏应用与游戏模式下可能表现异常，需实测确认。
* DPAPI 解密失败的处理必须足够健壮，不能出现启动崩溃。

### Suggested Phases

不建议按编号顺序开发，而应按风险与依赖排序。

* 依赖：无
* 说明：风险最高，早开工才有降级回旋余地。若中途判断不可行，立即启用降级预案并转入下一阶段

阶段四：体验治理（2.5 天）

* 关键交付：F3 剪贴板误触发治理与窗口改造（Issue #3）

* 说明：工作量第二大，敏感识别规则需预留实际使用校准时间

阶段五：信任补强（1 天）

* 关键交付：F4 API Key DPAPI 加密（Issue #5）

* 说明：可与其他阶段并行或作为收尾

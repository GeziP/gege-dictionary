# 鸽鸽词典可靠性加固设计

## 目标

把当前版本从“主流程可用”推进到“数据不丢、失败可恢复、界面状态与本地数据库一致”。本轮优先处理审计发现的 P0/P1：恢复文件校验、迁移目标安全、自定义目录失联、备份路径契约、导入后端边界、恢复/迁移后的前端重新加载、设置保存串行化、剪贴板首次轮询以及发布门禁。

## 约束

- 不修改 SQLite schema 版本，不删除旧数据库或旧版备份。
- 不增加网络遥测，不把真实数据库或 API Key 用于测试。
- 只在用户明确选择的目录内创建/清理临时产物；失败时保留原连接和原指针。
- 生产代码遵循 TDD：每项行为先有能复现缺陷的失败测试，再实现最小修复。
- 当前 checkout 的 `.commit_msg.tmp` 删除是既有工作区状态，保持不变。

## 设计

### 数据库验证与快照

所有复制通过 rusqlite Online Backup API 写入同目录临时文件，完成后运行 `integrity_check` 与只读 schema 契约校验，再用原子替换落盘。schema 契约包括核心表、关键列、FTS 虚表和触发器；仅有 `user_version=3` 的空壳数据库不得被接受。目标文件创建失败或校验失败时删除不完整临时文件，源连接不变。

恢复前先在 `backups/` 创建可见的安全快照。自动、预迁移和恢复安全快照使用统一命名/目录契约，旧备份不被自动清理；恢复列表只返回通过文件名白名单和校验的文件。

### 目录迁移与启动恢复

迁移前规范化并比较源/目标路径，目标必须是空目录（或由本次创建），并完成写入探针和空间检查。快照、词条/设置/复习数据/schema 校验、目标 `dataDir` 更新和 `data-dir.txt` 原子替换全部成功后才切换活动连接；任一步失败都保留旧连接、旧指针并清理本次产物。

启动时自定义目录只有在目录和已有数据库文件均可访问时才被接受。目录存在但数据库失联时进入显式恢复流程，不静默创建第二份空库；指针读取失败也走可见错误路径而不是 `expect` 终止。

### 导入边界

CSV/TSV 解析在 preview 和实际提交使用同一 10 MB/10,000 行限制；mapping 目标只能是公开词条字段，禁止覆盖 id、状态、时间戳和内部 data。格式错误行报告行号并跳过，数据库写入仍在单一事务中。

### 前端状态一致性

恢复和迁移成功后统一重新读取 words、settings、templates、usage、stats、backups、warnings，并同步 context refs，避免下一次全量保存把旧 `dataDir` 或旧设置写回。设置变更以确认快照和待处理 patch 队列串行落库；单次失败会从最后确认快照重建 UI，后续 patch 不会携带失败 patch。

开机自启统一通过 Tauri autostart bridge 调用，只有操作系统调用成功后才更新 UI。启动警告在应用级可见，而不是仅在某个设置页签加载后才出现。

### 查词行为

剪贴板 watcher 初始化时记录当前文本和 sequence，避免启动时把旧剪贴板误判为新复制；后续仍允许 sequence 变化的相同文本再次触发。流式请求保持“首字节前可降级一次、已有增量后只显示可重试错误”的单终态语义，前端忽略已经收到终态事件后的 invoke reject。

### 发布门禁

release workflow 补齐 `cargo fmt --check`、`npm test` 和 TypeScript `--noEmit`。前端修复明显的类型错误后，统一执行 Rust tests、lint、Vitest、typecheck 和 production build。

## 验证策略

按阶段执行红—绿循环：

1. 数据安全测试：坏 schema 恢复、迁移目标冲突/非空、备份路径契约、自定义目录失联。
2. 导入与前端状态测试：后端行数/mapping 边界、恢复/迁移刷新、设置失败后重放。
3. 查词与发布测试：首次剪贴板跳过、流式终态、CI 命令契约。
4. 全量门禁和隔离临时 `%APPDATA%` 回归；真实数据库与真实密钥不参与测试。

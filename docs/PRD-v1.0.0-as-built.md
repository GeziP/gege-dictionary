# 鸽鸽词典 / Gege Dictionary v1.0.0 — 实现版 PRD

文档状态：As-Built（描述已发布的 v1.0.0 实际形态，而非规划意图）
最后校准：基于 main 分支 README、源码结构与 v1.0.0 发布说明
前身文档：`PRD_LexNote — Windows 本地英文词汇笔记本`（已废弃，差异见文末附录）

### TL;DR

鸽鸽词典是一款 Windows 本地优先的英语查词与生词管理桌面应用。用户在任意应用中选中英文并按 Ctrl+C，应用通过剪贴板监控自动弹出查词窗口，由用户自行配置的 LLM（OpenAI / Anthropic 双协议）实时生成音标、语境释义、词根联想、例句、搭配与领域知识扩展，结果可一键存入本机 SQLite 生词库。产品无服务端、无账号体系、无数据上传，面向有真实英文阅读场景的技术与职场从业者。

## Goals

### Business Goals

* 以零服务端架构维持零边际运营成本：LLM 调用走用户自有 Key，分发仅承担 GitHub Release 带宽。
* 建立「复制即查」的产品认知，使安装用户中完成 LLM 配置并成功查询至少一次的比例达到 40%。
* 首月获得 3,000 次安装，验证「无服务端 + 自带 Key」的开源桌面工具分发路径可行。
* 激活用户 W1 留存不低于 35%，确认高频刚需属性而非一次性尝鲜。
* 平均每位激活用户生词库沉淀 ≥ 50 条，形成迁移成本与长期黏性。

### User Goals

* 不打断阅读流：在浏览器、PDF、Word、IDE、聊天软件中沿用既有的 Ctrl+C 肌肉记忆即可完成查词，无需学习新热键。
* 拿到超越传统词典的解析：语境义、词根词缀、近义辨析、可复用例句、常见搭配、语域判断。
* 处理长文本：段落可获得逐句对照翻译，句子可获得句法拆解，而非仅单词级查询。
* 获得专业领域深度：计算机、IVD 医疗、金融等领域术语自动补充背景知识与代码示例。
* 完全掌控数据与模型：数据留在本机 `%APPDATA%/GegeDic/`，模型与提供商可自由切换，包括完全离线的 Ollama / LM Studio。
* 生词库可搜索、可批量管理、可导出到 Anki / CSV / Markdown 继续使用。

### Non-Goals

* 不做内建的间隔重复复习系统（SRS）与每日复习队列，通过导出对接 Anki 等成熟工具。
* 不做多端同步、账号体系与云端服务器；不做 macOS / Linux / 移动端。
* 不做真人发音音频抓取与第三方词典授权内容，发音由 Windows 系统 TTS 承担。
* 不做整篇文档翻译、写作润色等通用 AI 助手能力。
* 不内置任何 API Key，不提供托管的免费额度。

## Functional Requirements

### 剪贴板取词与查词窗口（Priority: P0，已实现）

* 剪贴板监控触发：后台 `clipboard_watcher` 线程轮询剪贴板，检测到新的英文内容时自动唤起查词窗口。用户无需记忆专用热键，直接复用 Ctrl+C。
* 内容类型自动识别：区分单词 / 短语 / 句子 / 段落四类，分别路由到不同 Prompt 模板。
* 剪贴板去重：同一内容不重复触发查询，除非用户重新执行复制动作，避免窗口反复弹出与 token 浪费。
* 非英文内容过滤：中文或纯符号内容不触发查词，避免干扰正常复制操作。
* 查词窗口：独立 Lookup 窗口展示解析结果，支持关闭与再次唤起。
* 系统托盘常驻：主程序最小化到系统托盘，点击托盘图标打开主窗口（生词库）。

### LLM 解析引擎（Priority: P0，已实现）

* 双协议支持：同时兼容 OpenAI Chat Completions 与 Anthropic Messages 两套协议，覆盖 GLM、DeepSeek、OpenAI、Kimi、Anthropic、OpenRouter、Ollama / LM Studio。
* 自定义 Provider 配置：BaseURL、API Key、Model 名称可自由填写；内置常见服务商预设一键填充 BaseURL 与推荐模型。
* 连接测试：设置页提供「测试连接」按钮，返回可用性与错误原因（鉴权失败、超时、模型不存在）。
* 结构化输出：约束 LLM 返回 JSON，字段包括 word / lemma / pos / ipa_us / ipa_uk / context_meaning / senses[] / translation / explanation / associations / examples[] / collocations / register。
* JSON 容错修复：`llm.rs` 内置 JSON 修复逻辑，处理模型返回的截断、多余前后缀、非法转义等常见问题；修复失败时降级为纯文本展示而非报错。
* 段落逐句对照：段落模式输出 `translationPairs` 结构，原文与译文一一对应，前端以沉浸式交替排版渲染。
* 句子模式：输出翻译 + 句法拆解 + 关键词汇。
* 领域知识扩展：自动识别专业领域（计算机 / IVD 医疗 / 金融等），在解析结果中补充领域背景知识与代码示例。
* Markdown 富文本渲染：解析结果中的加粗、行内代码、列表等自动渲染，保证长解释与代码示例的可读性。
* 内置 Prompt 模板：模板与预设数据集中存放于 `src/data`，按内容类型与领域分发。

### 发音（Priority: P1，已实现）

* 音标展示：同时展示美式与英式 IPA，由 LLM 输出。
* 系统 TTS 朗读：通过 PowerShell 桥接调用 Windows Speech Synthesis 朗读单词与例句，离线可用，无需第三方音频资源。
* 快捷朗读：卡片内点击喇叭图标朗读当前词或例句。

### 生词收藏（Priority: P0，已实现）

* 一键收藏：查词窗口底部「加入生词库」按钮，保存 LLM 返回的全部结构化字段。
* 上下文留存：自动记录原句上下文与收藏时间。
* 收藏时快速标签：收藏动作中可直接输入标签。

### 生词库管理（Priority: P0，已实现）

* 列表视图：展示单词、翻译、词性、标签、收藏时间等字段。
* 详情面板：右侧详情面板展示完整解析，段落条目展示逐句对照译文。
* 搜索与筛选：按词形、释义、例句全文搜索，并可按标签组合筛选。
* 编辑：LLM 生成字段支持手动修改。
* 批量操作：批量打标签、批量删除、批量导出。
* 导出：CSV、Markdown、Anki 兼容 TSV，通过系统原生保存对话框选择路径。
* 导入：支持 CSV 导入已有词表。

### 设置与外观（Priority: P1，已实现）

* Onboarding 向导：首次启动引导完成 LLM 提供商选择、Key 填写与连接测试。
* 字体大小调节：查词窗口与生词库均支持实时调整字号。
* 数据位置：默认 `%APPDATA%/GegeDic/`，SQLite 单文件存储，用户可直接备份或纳入同步盘。

### 已知缺口（Priority: P2，v1.0.0 未实现，记录用于后续排期）

* 流式（SSE）渲染：当前为一次性返回，长段落解析存在明显等待，无渐进反馈。
* 本地结果缓存：同词同模型重复查询未命中缓存，重复消耗 token。
* 用户可编辑的 Prompt 模板编辑器：模板目前硬编码于 `src/data`，需改代码才能调整。
* API Key 加密存储：当前未使用 Windows DPAPI 加密，Key 以明文形式存于本地配置。
* 备份与恢复：无一键导出数据库文件与定时自动备份。
* 掌握度标记与重新解析：无三态掌握度筛选，无对已收藏词的重解析与版本回滚。
* 用量统计：无本地 token 消耗与查询次数统计面板。

## User Experience

### Entry Point & First-Time User Experience

* 用户从 GitHub Releases 下载 `鸽鸽词典_x.x.x_x64-setup.exe`（NSIS 安装包），双击安装。系统要求 Windows 10 (1803+) / Windows 11 并具备 WebView2 运行时。
* 首次启动进入 Onboarding 向导：
  * 第 1 步：选择 LLM 提供商。卡片式列出 GLM、DeepSeek、OpenAI、Kimi、Anthropic、OpenRouter、Ollama / LM Studio，自动填充 BaseURL、协议类型与推荐模型。国内用户优先推荐 GLM 与 DeepSeek。
  * 第 2 步：填入 API Key 并点击「测试连接」。失败时给出针对性提示（鉴权失败 / 网络超时 / 模型名错误），成功后才允许进入下一步。
  * 第 3 步：使用说明与首次试用。明确告知触发方式是 Ctrl+C 而非专用热键，并提供示例文本供用户立即体验一次完整查询。
* 向导完成后主窗口进入生词库页面，应用同时驻留系统托盘并启动剪贴板监控。

### Core Experience

* 步骤 1：用户在任意应用中选中英文文本并按 Ctrl+C。
  * 无需切换窗口或记忆新热键，完全复用既有复制习惯。
  * 剪贴板监控线程检测到新的英文内容，判定内容类型（单词 / 短语 / 句子 / 段落）。
  * 若内容与上次查询相同，去重逻辑拦截，不重复弹窗。
  * 若内容为非英文或纯符号，静默忽略，不打断用户正常复制行为。
* 步骤 2：查词窗口自动弹出，展示加载态。
  * 窗口置顶显示，用户视线无需大幅移动。
  * 加载态明确告知正在调用哪个模型，避免用户误以为程序卡死。
  * 请求失败时展示可读的错误原因与重试入口，而非原始报错堆栈。
* 步骤 3：解析结果渲染。
  * 单词模式：音标（美式 / 英式）、词性、语境义置顶，其后为常见义项、详细解释、词根词缀与近义辨析、领域知识、例句（含中文翻译）、常见搭配、语域标注。
  * 句子模式：整句翻译 + 句法拆解 + 关键词汇提取。
  * 段落模式：逐句对照排版，原文与译文交替显示，配合领域知识扩展。
  * 解析文本中的加粗、行内代码、列表按 Markdown 渲染；代码示例以代码块呈现。
  * JSON 解析异常时自动降级为纯文本，保证任何情况下用户都能看到内容。
* 步骤 4：朗读与收藏。
  * 点击喇叭图标调用 Windows TTS 朗读单词或例句。
  * 点击「加入生词库」写入本地 SQLite，可同时输入标签。
  * 收藏成功给出即时反馈，用户可直接关闭窗口回到原应用继续阅读。
* 步骤 5：回顾与导出。
  * 点击托盘图标打开主窗口进入生词库。
  * 通过搜索框与标签筛选定位目标条目，右侧详情面板展示完整解析。
  * 选中多条后批量打标签或删除；通过原生保存对话框导出为 CSV / Markdown / Anki TSV。

### Advanced Features & Edge Cases

* 完全离线模式：配置 Ollama / LM Studio 的本地 BaseURL 后，全链路无外网请求，适用于敏感文本。
* 超长段落：超出模型上下文窗口时需给出明确提示而非静默截断（当前为已知薄弱点，见缺口清单）。
* 剪贴板竞争：与密码管理器、剪贴板增强工具共存时可能出现误触发，用户可通过退出托盘应用临时关闭监控。
* 模型输出不稳定：不同模型对 JSON Schema 的遵循度差异显著，JSON 修复层是保证体验一致性的关键组件。
* 多显示器与高 DPI：查词窗口需在缩放比例不一致的多屏环境下正确定位与渲染。

### UI/UX Highlights

* 查词窗口尺寸紧凑，定位靠近用户操作区域，最小化视线移动成本。
* 字号可实时调节，兼顾高分屏与长时间阅读场景。
* 浅色与深色主题保持足够对比度，代码块与正文有清晰的视觉分区。
* 逐句对照排版通过缩进与色阶区分原文与译文，避免长段落阅读时错行。
* 所有异步操作（查询、TTS、导出）均有明确的加载态与完成反馈。

## Narrative

一位在读研究生正在啃一篇关于体外诊断（IVD）试剂稳定性的英文论文。他习惯性地用 Ctrl+C 复制了一句包含 `matrix effect` 的长句——过去这个动作只是把文本存进剪贴板，然后他要切到浏览器、打开词典网站、粘贴、再回来，一轮下来阅读节奏已经断了；更糟的是词典给出的「基质效应」四个字对理解那句话毫无帮助。

这一次，查词窗口在他松开按键后自动出现。窗口先给出整句的中文翻译与句法拆解，接着标出 `matrix effect` 在这句话中的具体含义，并补充了一段 IVD 领域的背景说明：为什么样本基质会干扰检测信号、常见的校正手段是什么。他点击喇叭听了一遍读音，点「加入生词库」，打上 `IVD` 标签，然后关掉窗口，继续读下一段——整个过程没有离开过 PDF 阅读器。

三周后论文读完，他打开鸽鸽词典的生词库，按 `IVD` 标签筛出 60 多条术语，导出成 Anki TSV 导入自己的复习牌组。这些条目里保留着当初的原句上下文，他不需要重新回忆「这个词当时是在哪儿看到的」。

对产品而言，这位用户完成了从安装到激活、再到沉淀数据的完整链路：他配置了自己的 Key（零服务端成本）、积累了 60 条本地生词（迁移成本），并且验证了核心假设——复用 Ctrl+C 这一既有肌肉记忆，比要求用户记住一个新热键的转化率更高。

## Technical Considerations

### Technical Needs

* 桌面框架：Tauri 2.0（Rust 后端 + WebView2 渲染），相较 Electron 大幅降低安装体积与内存占用。
* 前端：React 18 + TypeScript + Tailwind CSS + Vite。页面划分为 Library、Lookup、Onboarding、Settings。
* 后端模块（Rust）：
  * `lib.rs`：主逻辑、Tauri Commands、托盘管理、窗口调度
  * `db.rs`：SQLite 数据访问层
  * `llm.rs`：LLM API 调用、双协议适配、JSON 修复
  * `clipboard_watcher.rs`：剪贴板监控与去重
  * `tts.rs`：语音朗读
* 前后端通信：`src/lib` 下的 Tauri Bridge 层统一封装 Command 调用与类型定义。
* HTTP 客户端：reqwest（Rust 异步）。
* 数据库：SQLite via rusqlite（bundled），无需用户额外安装运行时。

### Integration Points

* LLM 提供商：OpenAI 协议族（DeepSeek、Kimi、OpenRouter、Ollama、LM Studio）与 Anthropic 协议族（Anthropic、智谱 GLM）。新增提供商仅需扩展预设配置，无需改动核心链路。
* Windows Speech Synthesis：通过 PowerShell 桥接调用，无第三方 TTS 依赖。
* WebView2 运行时：Windows 11 内置，Windows 10 部分版本需引导安装。
* Anki / Excel / Obsidian：通过 TSV / CSV / Markdown 导出对接，不做 API 级集成。

### Data Storage & Privacy

* 所有数据存储于 `%APPDATA%/GegeDic/` 下的 SQLite 文件，包括生词库、设置与使用记录。
* 无服务端、无遥测、无账号体系。唯一的外发数据是「选中文本 + 上下文 + Prompt」，且直接发往用户自行配置的 LLM 服务端点。
* 隐私声明需在 README 与应用设置页同时可见，这是本产品相对云端词典工具的核心差异点。
* 已知风险：API Key 当前以明文存储于本地配置文件，应在后续版本迁移至 Windows DPAPI 加密。

### Scalability & Performance

* 无服务端扩展性问题；性能瓶颈集中在单机侧。
* 生词库达到万级条目时，列表虚拟滚动与全文搜索索引需要验证，当前未做压力测试。
* LLM 响应时间由用户所选模型决定，产品侧可控的优化项是流式渲染与本地缓存，二者在 v1.0.0 均未实现。

### Potential Challenges

* 剪贴板监控是双刃剑：降低了学习成本，但也带来误触发与和其他剪贴板工具的竞争问题，需要持续打磨过滤规则。
* 模型输出一致性：不同提供商对结构化输出的支持差异大，JSON 修复层是维护成本最高也最关键的组件。
* 无流式渲染导致长段落体验明显劣于单词查询，这是当前最突出的体验短板。
* 明文存储 API Key 在面向技术用户的开源项目中会被直接提出质疑，属于优先级较高的信任缺口。
* Windows 单平台限制了潜在用户规模，但换取了 UI Automation / TTS / 托盘等系统能力的实现简洁度。

## Milestones & Sequencing

### Project Estimate

v1.0.0 已完成并发布（NSIS 安装包，Apache-2.0 开源）。以下为后续补齐已知缺口的排期建议。

* v1.1（体验补强）：Small，1–2 周
* v1.2（信任与效率）：Small，1–2 周
* v1.3（可定制性）：Medium，2–3 周

### Team Size & Composition

1 人全栈（Product + Engineering + Design 合一），配合 AI 编码助手。当前 v1.0.0 即以此模式交付，后续无需扩编。

### Suggested Phases

阶段一：v1.1 体验补强（1–2 周）

* 关键交付：SSE 流式渲染（先出翻译与音标，其余字段逐段填充）；本地结果缓存（同词同模型 30 天命中）；超长文本的上下文超限提示。
* 依赖：需确认各提供商的流式接口在 Anthropic 与 OpenAI 双协议下的差异处理。
* 成功标准：段落查询的感知等待时间下降，重复查询的 token 消耗显著降低。

阶段二：v1.2 信任与效率（1–2 周）

* 关键交付：API Key 迁移至 Windows DPAPI 加密存储；一键数据库备份与自动定时备份（保留最近 7 份）；本地用量统计面板（查询次数与估算 token）。
* 依赖：数据库结构变更需提供平滑迁移。
* 成功标准：隐私相关 Issue 归零；用户可自主完成数据备份与迁移。

阶段三：v1.3 可定制性与复习闭环（2–3 周）

* 关键交付：用户可编辑的 Prompt 模板编辑器（支持 `{{selection}}` / `{{context}}` / `{{native_lang}}` 变量与多套模板）；掌握度三态标记与筛选；已收藏词的重新解析与版本对比回滚。
* 依赖：模板编辑器需要与内置模板的默认值机制解耦。
* 成功标准：高级用户可在不改代码的前提下调整输出结构；生词库具备基础的复习筛选能力。

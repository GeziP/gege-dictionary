# v1.12 实机验收清单

适用版本：1.12.0（内置 OCR 引擎）  
目的：自动化测试摸不到的部分——安装包里的文件、真实屏幕上的截图取词、内存与速度、出错时的提示——在 Windows 实机上逐项验收。

这一版只改了截图 OCR 的识别引擎，其余功能没有动；A 组、C 组（Anki）、D 组、E 组沿用 [v1.6 清单](QA-machine-checklist-v1.6.md)，没必要重做。v1.6 清单里「OCR 语言包」前置条件和 B9（没装英文识别包时的提示卡）从 v1.12.0 起作废，其余 B 项仍然适用，见下面 B7。

## 环境前置

| 项 | 要求 |
|---|---|
| OS | Windows 10 1809+ / Windows 11 |
| 主验收机 | **没装英文 OCR 识别包**的电脑（中文系统，设置 → 时间和语言 → 语言和区域里只有中文）。这正是 v1.11.1 时读成 `He110`、要求去改系统语言的那种机器 |
| 升级路径 | 一台装着 v1.11.1 的电脑，用来试应用内更新 |
| 干净机器（可选） | 没装过任何 Visual C++ Redistributable 的 Windows（新建的虚拟机即可），验证随包带的运行库够用 |
| 安装包 | `Gege-Dictionary_1.12.0_x64-setup.exe`，约 14.6 MB（v1.11.1 是 5.2 MB） |

## A. 安装与卸载

| # | 步骤 | 期望 |
|---|------|------|
| A1 | 在装着 v1.11.1 的机器上「设置 → 应用更新」检查并安装 1.12.0 | 更新成功，应用重新启动，设置、生词库、API Key 都在 |
| A2 | 看安装目录（默认 `%LOCALAPPDATA%\鸽鸽词典`，以实际为准） | 程序旁边有 `onnxruntime.dll`（约 16 MB）、`vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll`、`msvcp140_1.dll`，以及 `licenses\` 文件夹（5 个文本文件） |
| A3 | 全新安装（先卸载旧版再装）后立即按热键截图取词 | 能用，不需要重启、不需要联网 |
| A4 | 卸载 | 上面的 DLL 和 `licenses\` 都被删掉，目录里不留下它们 |
| A5 | 设置页打开、改一项、保存 | 没有报错（旧设置里残留的 `ocr.language` 不应影响任何东西） |

## B. 截图 OCR

| # | 步骤 | 期望 |
|---|------|------|
| B1 | 在没装英文识别包的机器上按 `Ctrl+Shift+O`，框选网页或 PDF 里的一行英文 | 先出现压暗的冻结画面；框选后正确查词（不再是 `He110`、`Librany'`）；全程**没有**任何「打开系统语言设置」之类的提示 |
| B2 | 设置 → 截图 OCR 取词 →「检测 OCR 可用性」 | 绿色提示「内置 OCR 可用：自检读出了 N/9 个词，用时 … 毫秒」；检测期间按钮显示「检测中…」且点不了第二次 |
| B3 | 框选一段中英文混排的文字 | 中文和英文都读出来，行序与屏幕上一致 |
| B4 | 小字（约 12–14 像素）、深色主题里的浅色字、视频字幕、扫描 PDF 各框一次 | 读出来的就是框里的字；记下读错的地方（截图 + 原文） |
| B5 | 一个只有一个单词的很小的框（约 100×40 像素） | 能读出这个词（Windows 引擎在这种框上原来什么也读不出） |
| B6 | 框选一整页大小的区域 | 在 1–2 秒内出结果，应用不卡、不无响应；记下用时 |
| B7 | v1.6 清单 B 组其余各项：B1–B8、B10–B13（多屏、混合 DPI、纯色区域、Esc / 右键 / 取消、托盘进入、按住热键、DRM、截屏失败） | 与 v1.11.1 相比没有变化 |

## C. 速度与内存

用任务管理器（详细信息页，看 `gege-dic.exe` 的「内存（活动的专用工作集）」）。

| # | 步骤 | 期望 |
|---|------|------|
| C1 | 启动应用后什么都不做，记下内存 | 与 v1.11.1 相当：引擎没载入时不占内存 |
| C2 | 按热键、框选并识别一次，再记下内存 | 比 C1 增加约 50 MB（读很大的区域时瞬间可到 250 MB 左右，读完回落） |
| C3 | 之后闲置 2 分钟以上，再记下内存 | 回落，接近 C1 |
| C4 | 闲置之后再按热键识别 | 照常识别；第一次稍慢（约 0.3 秒）属正常，按热键到出现冻结画面没有明显变慢 |

## D. 出错时看得见（可选，需要动安装目录）

| # | 步骤 | 期望 |
|---|------|------|
| D1 | 完全退出应用，把安装目录里的 `onnxruntime.dll` 改名为 `onnxruntime.dll.bak`，再启动，按热键 | 框选窗里出现提示卡：「内置 OCR 引擎没能启动：找不到 OCR 运行库 …。请重新安装鸽鸽词典…」，只有「关闭」按钮；设置页「检测 OCR 可用性」给出同样的话（红色） |
| D2 | 不退出应用，把名字改回来，再按热键 | 恢复正常，不需要重启（失败不会被记住） |
| D3 | 干净机器：没有 Visual C++ 运行库的 Windows 上做 B1 | 能用（随包的 `vcruntime140*.dll`、`msvcp140*.dll` 够用） |

## E. 隐私

| # | 步骤 | 期望 |
|---|------|------|
| E1 | 识别时用资源监视器（网络页）或防火墙日志观察 `gege-dic.exe` | 识别本身没有任何网络请求（查词那一步会连你配置的模型服务，这是原有行为） |

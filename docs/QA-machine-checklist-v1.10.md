# v1.10 实机验收清单

适用版本：1.10.0  
目的：v1.10 新增的备用模型接手、批量补全、长列表手感、复习三档与周报导出，依赖真实的模型服务、真实的滚动与系统对话框，自动化门禁够不到；在装有 Windows 的真机上逐项验收。主路径（复制即查、OCR、Anki、更新通道）仍按 `docs/QA-machine-checklist-v1.6.md` 的 A–E 组执行，托盘与朗读等按 `docs/QA-machine-checklist-v1.9.md` 的 F–K 组执行（与 v1.9 相比没有改动，抽查即可）。

## 环境前置

| 项 | 要求 |
|---|---|
| OS | Windows 10 1809+ / Windows 11 |
| 模型服务 | 两个**不同**的、可用的 OpenAI 兼容（或 Anthropic）服务各一份 Key：一个做主模型，一个做备用模型。只有一个服务时，可以用同一家的另一个模型名做备用——但备用与主模型必须不是同一组 Base URL + 模型 + Key，否则不会生效 |
| 数据 | 一份 v1.9.0 时代的数据目录（含自动备份 `backups/gege-backup-*.db`、复习进度、历史），用于 R 组 |
| 词表 | 一份约 10 个**真实**英文单词的 CSV（用于 O 组，会真的请求模型）；一份约 5000 行的假词 CSV（只用于 M 组，**不要**拿去补全），生成方式见 M1 |
| 安装包 | `Gege-Dictionary_1.10.0_x64-setup.exe` 或本地 `npx tauri build` 产物 |

## L. 备用模型

| # | 步骤 | 期望 |
|---|------|------|
| L1 | 设置 → 模型服务 → 备用模型：打开「启用备用模型」，填入备用服务的 Base URL / 模型 / Key，点「测试备用连接」 | 显示真实延迟；把 Key 故意改错再测，显示真实的失败原因，而不是笼统的「失败」 |
| L2 | 保存后关闭并重新打开设置页 | 备用 Key 输入框只显示占位符，不显示明文；主模型的 Key 没有被改动 |
| L3 | 清空备用模型的「模型」字段 | 状态行写明「还缺 …，补全之前备用模型不会生效」 |
| L4 | 恢复备用配置；把**主模型**的 Base URL 改成一个连不上的地址（如 `http://127.0.0.1:9/v1`），复制一个没查过的英文词 | 查词结果由备用模型给出，卡片写明回答的模型并带「备用模型」徽标；设置 → 本地统计里的「备用模型接管」加 1 |
| L5 | 同一个词再查一次 | 直接命中缓存，不再请求备用；「备用模型接管」不再增加 |
| L6 | 把主模型的 Base URL 恢复，再把主模型的 Key 改错，查一个没查过的词 | **不**接手备用：直接提示 Key 有问题与「去设置」 |
| L7 | 把主模型改成连不上的地址，同时把备用的 Key 也改错，查一个没查过的词 | 错误卡片按主模型的原因（网络）给建议，并附上备用失败的原因 |
| L8 | 关闭「启用备用模型」，再让主模型连不上并查词 | 不触发备用（可在备用服务商的控制台或本机代理日志里确认没有请求） |
| L9 | 词条详情 → 重新解析（主模型连不上、备用可用时） | 重新解析成功，并标注「（备用模型）」 |

## M. 生词库长列表

| # | 步骤 | 期望 |
|---|------|------|
| M1 | 生成一份 5000 行的假词 CSV 并在生词库里导入：`"lemma,translation" \| Set-Content -Encoding UTF8 words-5000.csv; 1..5000 \| ForEach-Object { "word$_,释义$_" } \| Add-Content -Encoding UTF8 words-5000.csv` | 导入成功，生词库显示 5000 个以上的词 |
| M2 | 表格视图下快速拖动滚动条、滚动鼠标滚轮 | 没有空白闪烁；滚动条的长度与词数相符；滚到底时最后一行完整可见 |
| M3 | 选中一个词、全选、取消全选、切换排序、输入搜索词 | 每次操作立刻响应，没有明显卡顿；全选后选中栏的数字等于列表里的词数 |
| M4 | 滚到列表中间后，调整界面字号或切换浅色 / 深色，继续滚动 | 行高变化后行不漂移、不重叠，滚动条与内容仍然对得上 |
| M5 | 点一行 | 打开该词的详情；列表的滚动位置不跳 |
| M6 | 切到卡片视图后滚动 | 卡片完整、滚动顺畅；切回表格视图时位置合理 |
| M7 | 搜索把结果缩到 400 个词以内 | 所有行都直接显示；Ctrl+F 能在页面里找到其中任意一行 |
| M8（有读屏时） | 用讲述人读表格 | 报出的总行数是真实的词数，而不是已经绘制的行数 |

## N. 复习「有点难」与复习日历

| # | 步骤 | 期望 |
|---|------|------|
| N1 | 今日回顾：翻开一张卡，按 1 / 2 / 3（或点对应按钮） | 依次是「认识」「有点难」「不认识」；按钮的悬停提示分别写明「升一档，隔更久再见」「留在原档，明天再见」「回到 Box 1，明天再见」 |
| N2 | 把一个处在 Box 2 或 Box 3 的词答「有点难」，另一个答「不认识」，第二天再进入今日回顾 | 两个词都在第二天出现；「有点难」的词仍在原来的档位，「不认识」的回到 Box 1（学习洞察里的「复习档位」可以对照各档的张数） |
| N3 | 在卡片上按住数字键不放 | 只处理当前这一张，不会连续跳过后面的卡 |
| N4 | 点朗读按钮 | 只发声，不翻面、不显示释义 |
| N5 | 答完一轮 | 总结行写明答对、有点难、升档、回落的数量 |
| N6 | 学习洞察 → 「近 12 周的复习日历」 | 今天出现色块；鼠标悬停显示「答对 x，有点难 y，答错 z」；「易错的词」里能看到有点难的词 |
| N7 | 设置 → 复习与会话 | 「每日回顾」的说明与实际的三个答案一致（认识升一档、有点难留在原档、不认识回到第一档） |

## O. 批量补全

用约 10 个真实单词的 CSV 做（会真的请求模型，花一点 token）。

| # | 步骤 | 期望 |
|---|------|------|
| O1 | 生词库 → 导入一份只有 `lemma,translation` 两列的 CSV | 顶部出现「N 个词还没有义项和例句」，并给出预计用量与「开始补全」 |
| O2 | 点「开始补全」 | 出现进度条与「正在处理：xxx」；补完的词出现义项与例句，**导入的释义、笔记、标签、掌握度不变** |
| O3 | 运行中点「暂停」，再点「继续」 | 暂停后不再发新请求（正在进行的那个词会先完成）；继续后接着做 |
| O4 | 运行中点「停止」 | 先显示「正在停止…」，手头的词完成后显示「已停止：补好了 N 个词」；点「继续补全」从剩下的词接着做 |
| O5 | 补全进行中关闭并重新打开应用 | 不会自动继续；顶部再次提示还剩多少词，点「开始补全」接着做 |
| O6 | 补全完成后看设置 → 数据与隐私 → 用量，以及生词库 → 历史 | token 数增加；查询次数不变；历史里没有这些词的记录 |
| O7 | 选中其中几个仍然只有释义的词，点选中栏的「补全所选（N）」 | 只补全选中的那些；已有义项的词不会被处理 |
| O8 | 把主模型的 Key 改错后点「开始补全」 | 整轮立即停下，写明 Key 的问题并给出「去设置」，而不是把每个词都标成失败 |
| O9 | 设置 → 模型服务 → 批量补全：把「每天最多用」调到最低档（5 万 tokens），导入约 40 个真实词，开始补全（可选，会用掉约 5 万 token） | 补到额度附近自动停下，标题「今天的补全额度用完了」，剩下的词保持原样，说明明天可以继续 |
| O10 | 备用模型已启用时，补全过程中让主模型连不上（把主模型的 Base URL 改成连不上的地址） | 补全仍在进行（备用模型接手），已补全的词有义项与例句；「设置 → 本地统计」里的「备用模型接管」不增加（批量请求不计入统计） |

## P. 重新解析与词形

| # | 步骤 | 期望 |
|---|------|------|
| P1 | 收藏一个有词形变化的词（如 `running` 作为单独的词条），在词条详情里点「重新解析」，让模型返回原形「run」 | 出现「模型认为原形是「run」，你保存的是「running」」的选择条；此时词条与词库都没有改变 |
| P2 | 点「更新「running」」 | 内容更新，词条仍叫 running；可「回滚」 |
| P3 | 再做一次，点「另存为「run」」 | 新增（或更新）词条 run，running 保持原样；点「撤销」后新增的 run 被删除 |
| P4 | 词库里已有 run 时再做一次「另存为」 | 更新那个 run，没有出现两个 run |
| P5 | 点「都不要」 | 没有任何改动 |
| P6 | 选择条出现时关闭词条详情，再重新打开 | 没有任何内容被保存 |

## Q. 每周回顾与周报

| # | 步骤 | 期望 |
|---|------|------|
| Q1 | 学习洞察 →「每周回顾」 | 显示本周周一到周日；学习过的日子打勾；今天没学时有高亮环；之后的日子是虚线 |
| Q2 | 「每周目标」选「每周 5 天」 | 出现进度条与说明；关闭并重新打开应用后目标仍在 |
| Q3 | 把目标选成「每天」，在周中查看 | 若本周已有没学的日子，写明「剩下的日子不够补到 7 天了」 |
| Q4 | 切换洞察页的 7 / 30 / 90 天 | 「每周回顾」的内容不随之变化 |
| Q5 | 范围选「本周」，点「保存周报」 | 弹出系统保存对话框，默认文件名形如「鸽鸽词典周报-2026-10-05.md」（日期是那一周的周一）；保存后提示路径；在对话框里点取消则不出现任何提示 |
| Q6 | 用记事本打开保存的 `.md` | 中文正常；表格正常；数字与洞察页一致 |
| Q7 | 范围选「上周」，点「复制周报」，粘贴到笔记软件 | 内容是上周的；提示「已复制周报」；复制后不会弹出查词窗口 |
| Q8 | 周一与周日各看一次（可用另一台机器或等到当天） | 周日没有「还没到」的日子；周一只有今天一天 |

## R. 升级与数据

| # | 步骤 | 期望 |
|---|------|------|
| R1 | 用 v1.9.0 的数据目录启动 v1.10.0 | 先产生迁移前备份；生词、复习进度、设置、历史全部保留；原有复习的档位与到期日不变 |
| R2 | 设置 → 数据与隐私 → 恢复一份 v1.9.0 时代创建的自动备份 | 恢复成功并升级到 v7；今日回顾、学习洞察可用 |

| R4 | 设置 → 数据与隐私 → 用量 | 说明里写明「不含批量补全」的查询次数，以及批量补全的 token 也算在内 |

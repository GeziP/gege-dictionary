# 鸽鸽词典 V1.4 双领域深化规格

文档状态：执行版
目标版本：1.4.0
版本定位：把“领域 Profile”从 Prompt 偏好升级为计算机与 IVD 可感知、可复用的专业阅读体验。

## 1. 产品原则

- 选择领域后直接获得专业解析，使用领域能力不以导入术语表为前提。
- 个人术语表只解决固定译法、企业缩写和内部命名，不承担通用知识库职责。
- JSON / TSV 仅作为迁移和备份入口；普通用户优先使用逐条新增或粘贴 Excel 两列表格。
- 计算机和医疗 / IVD 为重点领域；通用、金融、法律保持现有基础 Profile，不继续平均扩张。
- 专业结构按相关性出现，不为满足版式强行生成代码、算法、流程、标准或临床结论。
- 全部数据继续保存在本机，领域深化不引入账号、云端术语库或额外服务端。

## 2. J0：低门槛术语体验

### 2.1 主流程

- “新增术语”继续提供英文术语、固定译法、领域和备注表单。
- 新增“粘贴表格”：接受从 Excel / WPS 复制的两列或三列内容。
  - 第一列：英文术语。
  - 第二列：固定译法。
  - 第三列：备注，可选。
  - 整批术语选择一个领域，默认当前 Profile。
- 表头为“术语 / 译法”或 `term / translation` 时自动跳过。
- 错误必须定位到行号；空行忽略；复用现有覆盖 / 跳过冲突策略与事务导入。

### 2.2 高级入口

- JSON / TSV 文件导入、导出和冲突策略收进“批量迁移与备份”折叠区。
- 不删除原有格式，以保持团队共享、版本管理和向后兼容。

## 3. J1：计算机领域结构

模型在 `computing` Profile 下按相关性返回可选顶层字段 `domainAnalysis`：

```json
{
  "domain": "computing",
  "overview": "专业概述",
  "mechanism": ["核心机制"],
  "workflow": {
    "title": "流程或架构",
    "steps": [{ "label": "步骤", "description": "作用" }]
  },
  "algorithm": {
    "name": "算法名称",
    "summary": "适用场景",
    "steps": ["步骤"],
    "timeComplexity": "O(n)",
    "spaceComplexity": "O(1)",
    "pseudocode": "纯文本伪代码"
  },
  "codeExamples": [{
    "title": "示例",
    "language": "python",
    "code": "可复制代码",
    "explanation": "关键说明"
  }],
  "tradeoffs": ["工程边界与权衡"]
}
```

- 非算法概念省略 `algorithm`；不适合代码时 `codeExamples` 为空或省略。
- `workflow.steps` 限制为 2–7 步，按执行流、数据流或依赖顺序排列。
- 代码以 JSON 字符串传输，由前端专用代码卡片展示，不要求模型生成 Markdown 围栏。
- 代码卡片展示标题、语言、说明和复制按钮；代码保持空白与缩进并支持横向滚动。

## 4. J2：IVD 领域结构

模型在 `medical_ivd` Profile 下按相关性返回：

```json
{
  "domain": "medical_ivd",
  "overview": "专业概述",
  "principle": "检测原理",
  "specimen": ["样本类型"],
  "analyte": "分析物",
  "workflow": {
    "title": "检测流程",
    "steps": [{ "label": "步骤", "description": "控制点" }]
  },
  "clinicalMeaning": "结果口径与临床意义",
  "performanceMetrics": [{ "name": "LoD", "meaning": "指标含义" }],
  "interferences": ["干扰因素"],
  "qualityControl": ["质控要求"],
  "limitations": ["适用边界"],
  "standards": ["直接相关且有把握的标准"]
}
```

- 不生成患者级诊断、治疗建议、未经上下文支持的阈值或参考区间。
- 样本类型和分析物仅在选中文本或上下文明确给出时返回，不列举假设性候选项。
- 标准仅保留与当前概念直接相关、名称及版本/年份明确的条目；不确定时省略，不以宽泛的实验室认可标准替代方法学标准。
- LoB、LoD、LoQ 等性能指标需说明统计方案依方法而定，不把“均值 + 3SD”等简化规则描述为普适公式。
- 明确区分检测原理、分析性能、临床性能和个体医疗决策。
- 工作流按前分析、分析、后分析顺序展示，限制为 2–8 步。
- 页面固定展示“知识解释，不构成个体诊疗建议”。

## 5. J3：兼容与安全

- `domainAnalysis` 为可选字段；v1.3 及更早缓存、收藏和导入数据无需迁移即可显示。
- 阻塞与流式路径复用同一领域 Prompt，流式增量事件支持 `domainAnalysis` 与 `domain_analysis`。
- 专业内容仍为不可信模型数据，只通过 React 文本节点渲染；不执行代码、HTML、Mermaid 或任意脚本。
- 流程图由前端根据步骤数组绘制，不直接执行模型生成的 Mermaid。
- 缓存键已包含领域、风格、模板和命中术语，切换领域不会复用其他 Profile 的结果。

## 6. 验收标准

- [ ] 不导入任何文件，选择计算机或 IVD 后即可获得对应专业结构。
- [ ] 从 Excel 粘贴 2/3 列可批量导入，表头、空行、错误行和冲突策略正确。
- [ ] JSON / TSV 保留但默认收进高级折叠区。
- [ ] 计算机结果可展示机制、线性流程、算法复杂度、代码或伪代码与工程权衡。
- [ ] 代码保持缩进、可横向滚动、可复制，复制内容与模型返回完全一致。
- [ ] 不适合算法或代码的词不会出现占位式伪内容。
- [ ] IVD 结果可展示原理、样本 / 分析物、流程、性能指标、干扰、质控、边界和标准。
- [ ] IVD 不输出个体诊疗建议，未知样本、分析物、阈值与标准不猜测。
- [ ] 旧缓存和旧收藏在缺少 `domainAnalysis` 时正常显示。
- [ ] 阻塞、流式、缓存和收藏往返均保留领域结构。
- [ ] TypeScript、lint、前端生产构建和 Rust 单测通过。
- [ ] 使用真实模型分别完成至少一个计算机和一个 IVD 查询的桌面端验证。

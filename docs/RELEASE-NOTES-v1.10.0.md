# 鸽鸽词典 V1.10.0

本版本让词典在模型不稳的时候还能用、在词库很大的时候还顺手，并补上三个让日常学习更完整的功能：复习多一档「有点难」、导入的词可以批量补全成完整词条、洞察页可以设每周目标并导出周报。

## 新功能

### 备用模型

- 「设置 → 模型服务」里，主模型下方新增「备用模型」，可以再配置一个模型服务（字段与主模型相同，Key 同样用 Windows 数据保护 DPAPI 加密，页面上只显示占位符），并有自己的「测试备用连接」。
- 主模型太忙（429）、服务出错（5xx）、超时或连不上时，自动改用备用模型再试一次；查词结果里写明是哪个模型回答的，备用回答时带「备用模型」徽标。「设置 → 本地统计」里多了「备用模型接管」次数。
- Key 无效、模型不存在、返回内容无法解析这类要你去改配置的错误**不会**触发备用，免得把问题盖住。主备都失败时，按主模型的原因给建议，并附上备用失败的原因。
- 默认关闭。**启用后，主模型出问题时备用服务会收到与主模型相同的选中文本与上下文**，请选择你信任的服务；关闭时不会向它发送任何内容。

### 批量补全

- 从词表导入的词常常只有词形和释义，没有义项和例句。生词库顶部现在会提示「N 个词还没有义项和例句」与预计用量，点「开始补全」就逐个用主模型补全；也可以选中几个词点「补全所选」。
- **只填空缺的部分**：你导入的释义、笔记、标签、掌握度与复习进度都不会被改动。
- 可以暂停、继续、停止。关掉应用、额度用完或服务出错之后，再点一次就从剩下的词接着补（还没补的词就是剩下要做的，不需要保存什么）。
- 「设置 → 模型服务」里的「批量补全」可以设每天最多用多少 token（默认 10 万，约 60 个词；选「不限制」才是没有上限）和请求节奏（从容 / 标准 / 较快）。额度按今天查词与补全一共用掉的估算 token 计算。
- 遇到每个词都会遇到的问题（没有 Key、Key 被拒、模型不存在、一直被限流）整轮停下并告诉你原因与「去设置」，而不是把每个词都标成失败；只和某一个词有关的失败会列在「没补成功的词」里。

### 复习「有点难」与复习日历

- 复习多了一个答案：**认识（1）/ 有点难（2）/ 不认识（3）**。「有点难」让词留在原档、明天再见——刚好想起来的词不会一下子跳到一周之后。
- 学习洞察新增「近 12 周的复习日历」，每天按答题数着色，鼠标悬停可以看到当天答对、有点难、答错各多少；「易错的词」按「答错 × 2 + 有点难」排序；答对率把「有点难」算作没答对。

### 每周回顾与周报

- 学习洞察新增「每周回顾」：本周（周一至周日）每天是否学习过（查词、收藏或复习算一天），以及你设的每周目标（1–7 天）——已达成、还差几天、或本周剩下的日子已经不够了。
- 「保存周报 / 复制周报」把本周或上周整理成一份 Markdown：逐日表、复习作答情况、词库现状（常查与易错的词）。数据只来自本机记录；缺数据时会说「没有读到记录」，而不是写成「没学」。

## 变化与修复

### 生词库

- **长列表更顺**：超过 400 个词时，表格只绘制屏幕上的行，滚动与选中不再随词库增大而变慢；滚动条仍然是整个列表的长度。表格里每个词占一行（过长的内容截断，完整内容在详情里）。卡片视图仍绘制全部卡片，但屏外的会被浏览器跳过。
- 洞察页里的「本周新增」改名为「近 7 天新增」——它一直是滚动 7 天，不是日历周。
- 掌握度选择菜单按词的成长顺序排列（新词、巩固中、熟悉、已掌握）。

### 重新解析

- 重新解析「running」得到的原形是「run」时，**不再悄悄给词条改名**：会问你「更新「running」/ 另存为「run」/ 都不要」，回答之前什么都不保存。词库里已有「run」时，另存会更新它，不会出现两个「run」。「更新」可以回滚，「另存」可以撤销。
- 后端也不再允许「按 id 保存另一个词形的答案」，任何入口都不能靠重新保存给词条改名。

### 今日回顾

- 按住数字键不再连续跳过后面的卡片：一次只保存一个答案。
- 保存答案失败时卡片保留并说明原因，而不是丢掉这次作答。
- 朗读按钮只发声，不再翻面泄露释义。
- 「设置 → 复习与会话」里「每日回顾」的说明已改为三个答案各自的后果。

## 工程

- 固定 Rust 工具链（`rust-toolchain.toml`，1.95.0），CI 与发布流程都用它，并且 `cargo clippy --locked --all-targets -- -D warnings` 不过就不能合并；新的稳定版 Rust 不会再让无关的 PR 变红。
- schema 升到 v7（`review_state.hard_count`）；升级前自动备份，失败回滚；旧版本做的备份仍可恢复，恢复后自动升级。
- 复习的调度规则抽成纯函数（`review.rs`），批量补全的规则放进 `enrich.rs`，周的推算与周报放进 `weekly.ts`，都有单测。
- 版本三处同步 1.10.0。

## 升级说明

- 首次启动 v1.10.0 会把数据库从 v6 升到 v7，并先自动备份；失败会回滚。没有测试过用 v1.9.0 打开 v7 的数据库；需要退回旧版本时，请退出应用，把数据目录 `backups/` 里升级前留下的 `gege-premigrate-v6-….db` 复制成 `gege.db`（同时删掉同目录下的 `gege.db-wal` 与 `gege.db-shm`，如果有的话）。应用内的「恢复」只列出自动备份，不提供迁移前备份。
- **复习的数字键变了**：键 2 原来是「不认识」，现在是「有点难」，不认识改为键 3。
- 备用模型默认关闭；批量补全不会自己运行，只有点了「开始补全」才会请求模型，并受每日额度约束。
- 批量补全用掉的 token 计入「设置 → 数据与隐私 → 用量」里的 token 数，但不计入查询次数，也不会出现在查词历史里。
- 重新解析遇到词形变化时的行为变了（先问，而不是直接改名）。
- 每周目标默认不设，在学习洞察的「每周回顾」里选择。

## 验证

开发机上的自动化检查全部通过：`cargo test --lib` 300 项、`cargo clippy --locked --all-targets -- -D warnings` 零警告、`cargo fmt -- --check`、`tsc --noEmit`、`npm run lint`、`npm run build`、`npm test`（28 个文件 447 项）。

自动化测试够不到真实的模型服务失败、系统保存对话框与长列表的实际手感，所以请按 `docs/QA-machine-checklist-v1.10.md` 的 L–R 组在 Windows 实机验收。其中最需要实机确认的是：

- 备用模型真的接手：把主模型的地址改到一个连不上的服务后查词，结果由备用模型给出并带「备用模型」徽标；把主模型的 Key 改错则**不会**接手，而是直接提示 Key 的问题。
- 批量补全：导入一份只有「词 + 释义」的词表后，开始 / 暂停 / 停止都按预期；原有的释义与笔记没有被改动；额度用完会自动停下。
- 「今日回顾」页的键 1 / 2 / 3 与按钮提示一致，「有点难」的词第二天再出现。
- 五千词以上的词库在表格视图里滚动流畅，滚动条长度与词数相符，最后一行能滚到。
- 周报：保存的 `.md` 文件用记事本打开中文正常，表格与洞察页上的数字一致。
